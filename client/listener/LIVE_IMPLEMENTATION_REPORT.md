## 单一业务源码与独立监听模块

用户进一步要求监听成为单独模块，公共逻辑以后只修改一份。现在模块位于 `client/listener/module/`，公共入口 `module/index.ts`，包含订阅、通知合并、串行执行及接入原方法的生命周期。模块职责与维护方式见 [模块说明](./module/README.md)。

监听入口 `module/bootstrap.ts` 只导入原 `client/web/src/main.ts`，因此原启动以后增加、删除或调整公共初始化，两版构建都会采用。原 store 的 start/stop/fetch 动作通过保存的原函数调用；`runMainLoopTick`、`scheduleMainLoop` 保持原方法引用，原循环负责状态回写、原 finally、等待和重调度。监听适配层仅串行调用原循环体，不复制其业务或定时实现。

已删除监听版复制的启动、鉴权函数和循环宿主。鉴权和路由现在直接使用原文件，构建时仅在内存适配返回 URL 与 history。旧副本上的鉴权测试替换为原函数/API 回归与转换边界检查；串行测试改为直接覆盖新模块，而非引用历史离线队列测试。

公共源码只有一份，修改后两版各自构建均使用新实现，无须人工同步另一份业务代码。当前监听版仍是预构建产物，开发时需运行独立构建再刷新，原 `npm run dev` 尚不自动重建监听 bundle；“源码共同采用”不应解释为已经实现双页面同步 HMR。

```powershell

```

## 现在实际替换什么

监听页面通过原启动创建自己的 Vue/Pinia 实例，页面和业务直接导入原实现。新增构建 alias 仅覆盖 match store 模块接入、主循环体的串行适配和全盘口套利扫描入口；路由/鉴权落点通过原文件的内存转换适配，不再提供另一套启动、主循环宿主、预检、鉴权或组件副本。

| 部分 | 当前实现 |
| --- | --- |
| App、GateView、HomeView、各设置/账号/订单/管理页面 | 直接复用原组件、样式和操作；已移除额外状态栏和页面高度覆盖 |
| 启动、登录、Cookie/CSRF、续期、sessionRecovery、钱包及 appSession 生命周期 | 直接运行原 main.ts 和原鉴权函数；构建时只把鉴权重新登录落点保留在监听地址 |
| 路由和权限 | 构建时只在内存替换原 router 的 history 创建方式；完整保留原 routes、guards、管理员/团队长权限和返回控制台逻辑，不写原文件 |
| 配置与前端门控 | 从原 `client/web` 加载同一 `VITE_*` 环境；本机开发 bundle 使用相同 DEV/PROD 标志；不强制 Cookie 模式，不绕过原插件/证书门控 |
| 列表与初赔 | 调用原 store 上绑定的 `fetchMatches`；原列表转换、失败/空列表语义、索引及初赔等待均保留；手动刷新仍各自调用原函数 |
| 周期维护 | 原 store 的 tick、schedule 和 finally 方法仍负责循环，原 `runMainBetLoopTick` 只经串行适配；保留列表轮询、清理、补单、初赔和扩展逻辑；变价通知不会额外唤醒 EV/提前锁利维护 |
| 套利执行链 | 直接调用原 `runArbBetRound`，保留待补绑 → 套利 → 补单顺序；原 prepare/check/place/finalize、FOK/GTC、随机金额和账号规则不变 |
| 套利盘口来源 | 将原 `runA8ArbRound` 全量扫描替换为变动盘口集合；每盘口建立依赖监听，通知合并，批次按原列表顺序串行进入原执行入口 |
| 持续机会 | 已尝试盘口约 100ms 后独立重验，允许原预检拒绝后的恢复和下一次随机金额抽取；不以旧随机金额提前排除尝试 |
| 开赛时间 | 原赛前过滤规则不变；监听过滤模式、时间变更，并为 startAt 安装/重排/取消到期唤醒 |
| 停止与执行收尾 | 调用原 stop，停止未来调度；已进入原执行批次按原链路收尾。不再额外拦截预检、按对象身份取消任务或包装 logout 等待 |
| 分包恢复 | 使用原 chunkReload 处理；本机加载器读取当前 HTML，bootstrap 带构建内容标识，避免原 Vite 缓存旧监听入口 |

队列只串行化本监听调度产生的套利/维护轮次，不对原 App 中独立的人工操作、订单监控或异步 EV 策略新增全局锁。异步扩展仍按原循环 fire-and-forget 并隔离错误；不能把它们描述为已被新队列全部串行化。

## 对齐与交付边界

“业务规则复用并已对齐上述差异”不等于真实成交结果必然逐笔一致：监听通知发生在不同时间，能捕获原下一轮扫描前已经消失的机会，实际赔率、成交和次数可能随之不同。这正是更换检测模式的直接结果。随机金额仍是原每次尝试抽取，不能要求两次独立运行随机数相同。

当前自动验证使用 mock I/O，不登录账号、不修改用户下注开关、不提交订单。尚未进行带登录状态的全页面操作、真实行情/场馆错误、钱包/扩展交互及多用户负载验收；这些未覆盖部分不能写成已经证明所有效果绝对一致。

原首页未导入监听模块，原循环/共享包/后端/数据库/既有 npm、Vite、部署配置均未改。本任务前已有的 `packages/shared/package.json`、`scripts/catalog-smoke.mjs` 差异原样保留。两版仍访问共同后端/RDS和原接口，监听用户的操作照常保存到原账户；源码隔离不代表共享服务在任意负载下都不存在间接影响。

当前产物是本机开发入口，资源使用 `/@fs/E:/...`，不属于已经接入原生产发布流程的可部署制品。独立生产资源路径、发布准入、托管、CI、部署/回滚仍待后续授权和验收。没有提交、推送、部署，也没有修改现有工作区之外的服务。
