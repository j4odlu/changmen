# PM 报价转换边界

[changmen 扩展] 电竞 PM 报价处理采用以下链路：

```text
场馆采集器 → oddsStore 原始行情
                     ↓
       原始卖一 + 报价规则 + tick 元数据
                     ↓
         priceQuote.ts 纯报价转换
                     ↓
       UI / 套利选腿 → 冻结报价 → 预检 / 下单
```

`packages/venue-adapter/polymarket/priceQuote.ts` 负责百分比和 +1 tick 的转换。
它不读取 store、配置或时钟，不发 HTTP，不修改采集行情。
百分比沿用卖一乘 multiplier、四位价格精度的规则；tick 模式按该市场的一个 tick 增加卖一。
两种模式均从调整价格取倒数，截断为 UI 使用的三位赔率。
报价配置镜像更新后，`onPmPricePolicyChange` 通知消费者重新读取结果，覆盖百分比启停、倍率和模式变化。
通知不写入原始行情，也不触发百分比模式的 tick HTTP 预取；已冻结订单继续使用原报价。

`oddsStore.getPmQuoteEntry` 是电竞报价消费者的共同原始行情入口。实时条目优先；
采集轮次清空 PM 缓存时，保留完整卖一、原始赔率、盘口 ID、锁盘状态和原始时间的只读快照。
UI 和新建订单继续从快照转换，配置切换不会重复处理旧展示赔率。
锁盘更新同时作用于重建期间的快照；沿用 `clean()` 的一小时失效窗口，过期行情不能由旧展示数字恢复。
`save`、`getEntry` 和 `isOdds` 仍保持采集层原有行为，不把快照写回采集缓存。

`pmTickMetadata.ts` 单独维护 tick。已确认的值不会因到达刷新时间或切换配置而失效；
较新的 WS 事件优先于旧 HTTP 结果。队列按真实在途请求限制为 4 并发。
`runtime/pmTickBufferQuotes.ts` 只预取当前比赛中有有效卖一且未锁盘的 PM 资产。
首次缺少 tick 时 UI 显示“等待报价”，该资产暂不参与套利。

`domain/polymarket/tickBufferQuote.ts` 在建腿时冻结原始卖一、转换规则、精确价格上限和展示赔率。
手动下单在金额框打开前冻结。随后行情或配置改变，不重算已有尝试的报价。
预检核对最新订单簿与 tick；价格超出上限时拒绝本次尝试。
百分比模式在已知 tick 变化后核验冻结限价是否仍在有效档位；+1 tick 模式还要求 tick 与冻结报价一致。

PM BUY FOK 使用冻结上限；预检依据当前订单簿 tick 确定并冻结实际签单限价。
百分比上限不在 tick 网格时，实际签单限价向下对齐，不能超过上限。
+1 tick 的签单限价等于冻结上限。预检后的编排赔率继续使用冻结展示赔率，
订单簿实际赔率单独保存在预检数据中。提交、诊断日志和上限内深度统计直接读取冻结上限，
不再从三位展示赔率取倒数还原价格。UI 随新行情更新，已有尝试继续使用自己的冻结报价。
两种模式的最小份数统一按实际签单限价及当前 SDK BUY 编码精度预检，金额保持用户原值；
签单完成后还核对 SDK 返回的实际份数，低于市场最小值时禁止 POST。
双腿发单前、签单完成后及取得浏览器提交锁后复用同一执行价格校验；
等待期间收到 tick 变化且冻结限价已无效时中止该尝试，不重新定价。
场馆价格和状态仍由采集来源提供，执行校验不依赖 UI 是否显示赔率。

体育板和 POD 仍使用独立报价路径；传统场馆保持原有展示和下单处理。
