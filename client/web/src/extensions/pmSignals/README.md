# PM 赔率异动

[changmen 扩展] 浏览器内统一检测和展示涨赔、降赔信号，使用 changmen 已接收的行情，不选号或下单。

在用户中心「界面 → 赔率异动」统一配置两种监测，也可在浮窗快捷切换监测开关。修改立即生效，点击用户设置页「保存」后持久化到当前用户。默认监测和角标均关闭；涨赔默认任意实际涨幅、最小理论套利空间 1%、观察窗口 5 秒、冷却 10 秒；降赔默认降幅 5%、窗口 5 秒、冷却 10 秒。界面统一用秒，内部仍用毫秒。监测独立于主套利开关，角标显示开关独立于监测。

- `runtime.ts` 是唯一监测入口，只注册一个 `onPolymarketMarketQuote` 回调，涨跌共用有界队列和分批异步处理。只启用非 PM 降赔基准时不监听 PM，按需只读轮询；两边均关闭时不注册行情回调或定时器。不增加网络订阅或请求，不等待主套利执行。
- 降赔由 `downDetector.ts` 判断窗口内降幅，`downVenueSnapshot.ts` 冻结同一合场盘口、同方向的各场馆报价，`downMatchSignals.ts` 关联盘口。基准可选择 PM、OB、RAY 或 PB。
- 原始 PM 卖一 `bestAsk` 下跌代表十进制赔率 `1 / bestAsk` 上涨。仅新涨价事件触发判定；窗口内最低赔率为涨幅基线，首次报价和长于窗口的行情间隔只建立基线。
- 通过 PM token 索引定位同一合场盘口的规范方向；PM Home 涨赔时读取其他场馆 Away，PM Away 涨赔时读取其他场馆 Home。每个场馆取最高有效赔率，排除锁盘及无效报价。
- 利润口径为 `(1 / (1 / PM赔率 + 1 / 场馆对侧赔率) - 1) * 100`，必须为正且达到配置阈值。PM 使用原始行情，不受展示缓冲设置影响；展示的是报价层理论套利空间，未做可成交深度或下注预检。
- 收到行情时冻结对侧报价，再分批异步计算；同一盘口、PM 方向、目标场馆选项独立冷却。持续未变价不会重复触发，只有场馆变价也不会触发。
- 涨跌共用一个浮窗，可按全部/降赔/涨赔筛选、拖动、缩放和清空。固定展示 PM 变价方向、前后赔率，再展示对侧场馆的队名与报价、理论套利；降赔的同向价差单独标注。
- 涨赔表示 PM 涨价时存在符合阈值的对侧套利空间，尚不证明此次涨价首次创造了套利机会。
- 开启 BetRow 扩展 UI 后，赔率左侧保留现有即时涨跌箭头；PM 赔率右侧同时显示涨跌幅和触发时的前后赔率（三位小数）。两个赔率在左侧上下排列，高赔率在上、低赔率在下，箭头和百分比位于其右侧并垂直居中；后续实时变价不改写该快照。降赔对应场馆同侧显示“高+百分比 / 低百分比 / 持平0.0%”，悬浮说明明确其相对 PM 降后赔率的高低，涨赔对应场馆对侧显示“套”。严格按合场盘口及触发时选项 ID 关联，不用当前最优报价反推。角标保留 30 秒，10 秒后淡化；点击打开统一浮窗对应快照，不触发选边或下注。关闭 BetRow 扩展 UI 只关闭行内角标，浮窗监测继续工作。
- 涨赔最多保留 100 条，关闭或修改涨赔参数时重置该策略并清空其历史；退出页面或换用户时停止监测并清空两种记录。清空按钮同时清除两种显示记录，不重置检测基线或冷却。

源码：`upSettings.ts` / `downSettings.ts` 分别维护配置，`upDetector.ts` / `downDetector.ts` 为纯判定策略，`upMarkets.ts` 负责涨赔合场映射和报价快照，`records.ts` 集中存放两种信号记录，`state.ts` 合并展示列表。`runtime.ts` 是唯一监测入口，`useSignalMonitors.ts` 管理用户生命周期。涨跌策略窗口、阈值和冷却独立，修改一边配置不会重订 PM 回调或清空另一边的基线；涨赔参数变更或降赔监测场馆切换时，会丢弃对应策略过期的排队任务。保留原 `pmUp`、`pmOddsDropCardUi` 用户偏好及 `changmen:pm-odds-drop:settings:v1` 本机配置键。

`SignalSettings.vue` 是统一配置界面，`useSignalSettings.ts` 为浮窗和监测提供同一份用户设置。新增 `pmDown` 保存降赔参数、`pmUpCardUi` 独立控制涨赔角标。加载旧用户配置时，仅缺少 `pmDown` 才读取旧本机 key 迁移；已保存的用户配置优先，旧 key 不再写入。缺少 `pmUpCardUi` 的旧用户沿用原涨赔开关的角标可见性，显式保存后监测与显示完全独立。以上信号配置不接入自动下注或套利来源归因。

涨跌比较报价均在行情入队前捕获，异步判定不读取后来的场馆价格。PM 合场索引使用惰性计算，同时响应列表替换及响应式列表中的选项原地替换；不会按每笔报价重扫未变化的全列表。
