# 数据库升级兼容与代码回退

第四轮，2026-10-15。属于解耦方案批次 3。当前只新增测试、流程与文档，没有生产 DDL、业务代码、HTTP 或前端行为变化。

## 当前执行边界

日常应用部署不执行数据库维护，不扫描重放历史 SQL，也不补写迁移账本。`check:rds-schema` 是独立的只读结构核验，`db:initialize` 只用于显式初始化空库；已有业务表时拒绝初始化。

涉及必需结构变化的发布，维护流程应为：备份与兼容演练 → 执行经过审批的目标增量 → 用候选代码的结构清单运行只读核验 → 核验成功后发布应用。核验非零退出时停止发布，保留旧进程；不能用 `db:initialize`、修改清单或重放历史 SQL 来消除报错。

**现有 Actions 应用部署没有自动结构前置闸门**。本轮验证的是只读命令的真实失败退出与手工维护顺序，不宣称缺字段会被现有部署流水线自动拦截。是否把这项核验接入正式发布，需要另行设计生产只读连接、权限和发布分类；本轮保持现有部署行为。

## 每项增量的变更记录

| 必填项 | 需要说明的内容 |
| --- | --- |
| 版本 | 固定旧代码 SHA、候选代码、旧结构清单和新增要求，不能用移动的 HEAD 代表旧消费者 |
| 结构 | 明确新增或改变的列、表、约束、索引、函数、触发器及 checksum；不得从生产自动录制成期望 |
| 数据 | 受影响表与行范围、空值/旧值处理、是否回填；回填与 DDL 分开说明并支持恢复 |
| 锁 | 锁类型、锁等待与语句超时、并发读写影响；并发索引必须单独设计，不能塞进普通事务 runner |
| 兼容 | 旧代码读取和写入新增结构；候选读取旧数据；代码回退后的行为 |
| 失败 | 事务回滚、已提交步骤的保留、重试幂等性、账本 checksum、锁释放 |
| 发布 | 提供方先发布的顺序、候选只读核验结果、是否需要前端发布与依据 |
| 恢复 | 代码回退窗口、保留兼容新增结构、需要人工数据恢复的步骤与备份位置 |

优先增加 nullable 列、独立表和兼容索引。新增必填列、唯一约束或触发器即便是“新增”，也可能破坏旧代码写入，必须增加具体兼容样本。只有旧代码退出回滚窗口后，才考虑删字段、删兼容逻辑或收紧约束。

旧库增量只传入目标 SQL 的显式清单。`runRdsMigrations` 负责会话锁、逐项事务与同事务账本记录，不代表它会替维护者判断 SQL 是否兼容。多项清单中已经提交的前项不会因后项失败自动撤销；涉及数据转换时必须单独定义恢复方案。

## 可复现的本地演练

```text
npm run test:schema-compat:postgres
npm run test:deploy-safety:postgres
```

需要本机 PostgreSQL 的 `initdb`、`pg_ctl`，放在 PATH 或设置 `CHANGMEN_TEST_PG_BIN`。脚本创建全新临时集群并只监听 `127.0.0.1`，在导入应用模块前覆盖所有数据库地址选项，不读取真实 RDS 数据；结束时停止并删除临时集群。不要用 root 运行 `initdb`。

`scripts/testing/schema-compatibility/reference.json` 固定第三轮已发布提交 `9aa9159ce6b531153bd5321f89f2fcd19002671e` 的 52 个 Git blob 及 SHA-256。缺少该 Git 对象或校验不一致直接失败，不会改用当前源码。旧库只由固定版本的迁移 SQL 初始化，候选版本的空库初始化在另一数据库独立检查，避免用候选结构冒充旧库。旧消费者、旧结构核验器与候选在不同 Node 进程运行，连接同一临时数据库；数据库驱动来自当前已安装依赖。本轮演练的是实际数据模块，不等同于完整旧版 HTTP 服务、浏览器或全部投注流程演练。

测试专用 `expand.sql` 只位于 `scripts/testing/schema-compatibility/`，不在生产迁移目录或初始化清单。样本增加一个 nullable 字段、一张表和索引，期望结构是人工固定定义。它不代表有新增生产字段的业务需求。

覆盖空库核验失败与显式初始化、旧/新代码读取旧数据、候选更新旧数据、升级前缺必需结构失败、显式增量和账本、旧检查器容忍新增结构、升级后新旧读取与创建用户、代码回退保留未来数据、重复执行、checksum 漂移、DDL/DML 回滚、锁超时与锁释放、真实核验 CLI 非零退出、无账本与空账本保持只读。既有部署保全测试继续覆盖应用激活不运行维护，以及账号、权限、序列的保护。

CI 日志管道显式启用 `pipefail`，并以退出码 0 与 23 的真实 shell 回归证明日志保存不会吞掉失败。固定引用和样本隔离检查接入 `verification-control`；真实 PostgreSQL 演练有独立 `Database compatibility` 工作流（PR、master 相关路径和手动触发），不需要生产密钥。该工作流是独立检查，未改动现有发布工作流的依赖关系，也不会部署应用。
