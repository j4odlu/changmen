## 强制检查

```text
npm run check:fok-vps
```

检查 550 个保护源码的文件哈希，并核对全部基线文件的 Git 来源。公共 writer 仅允许两个明确的模式扩展 import 和对应语句；去除这两个边界后，完整模块及所有原 import 必须与基线一致。此命令使用本地固定基线，不依赖当前网络或 VPS 在线。

同时校验下列边界：

- 自动编排仅将入口 import 指向模式分发器；FOK 的原准备、预检、下单、重试、补单及收尾实现不改。
- 完整手动入口在 FOK 选择下与原实现逐语句等价。校验包含选号、报价冻结、金额校验、账号过滤、余额检查及原执行体。只归一化模式选择 UI、将独立执行函数的参数还原到原作用域，并展开实际 FOK 执行函数。
- 公共订单详情的附加入口不改变普通卡片的金额、盈亏及按钮条件。金额插槽的默认内容保持原表达式。
- FOK 自动卖出只调整订单来源以排除 GTC 原单，既有扫描与卖出执行体不改。
- 49 个既有订单相关函数在 FOK 输入下与基线一致；PM adapter 的 29 个既有函数体一致。
- 18 个自动执行、19 个手动执行场景及 4 个收尾组合对比实际旧/新实现的参数、调用顺序与结果；包含取消、缺少账号、预检失败、POST 异常、待确认、明确拒单和同步异常。
- GTC 模块不能调用 FOK 私有补单、成功历史、提交缓存或收尾动作，不能建立第二套普通订单统计和报表。

## 本次收紧的保存边界

普通订单读写入口直接导出原 `handleGetOrderList` / `handleSaveOrder`，不解析、分批或查询 GTC 执行记录。历史模式保护复用普通 writer 原有的唯一严格读取，不增加回退查询。FOK 请求的原验证、严格读取失败规则、普通 upsert 和响应保留。

删除 GTC 复制的普通订单 writer。GTC 专用接口完成自己的账号归属和原单校验后，也调用公共 writer；已核实成交成本的 GTC PM 买单使用其已有 SQL 保护，防止旧场馆快照覆盖已核实成本。普通 FOK 批次不调用此 SQL；混合批次中的 GTC 刷新等待或失败不阻塞 FOK 保存。

GTC 查询、历史模式修复和挂单恢复只在 GTC 模块中执行。前端历史恢复改为观察公共 OrderStore 的原单身份，管理员预览不能启动被预览用户的交易恢复。两种模式进入同一订单栏和统计，买入成本包含手续费。已有 GTC 导致的真实余额、订单数量或账号轮转变化属于公共输入变化，不修改 FOK 原计数和选号规则。

## 保证的含义

这里保证的是相同账号、订单、行情、配置和场馆响应输入下，FOK 原有算法与上述 VPS 版本一致；不是保证不同行情、余额或网络状态下的结果数值相同。模式选择和历史订单身份路由属于新增边界，单独验证，不能用核心文件一致代替这些边界的验证。
