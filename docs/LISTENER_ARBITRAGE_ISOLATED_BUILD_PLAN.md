# 监听套利独立构建方案

日期：2026-10-28。标记：[changmen 扩展]。

2026-11-06 更新：用户确认采用简化交付，两版分别构建并合入一个前端包，`/` 与 `/listener/` 一起发布、一起回滚。独立生产版本及独立部署流程不再采用；当前实现见 [监听说明](../client/listener/README.md)。下文保留早期设计记录。

状态：以下主体保留最初设计依据。用户后续确认采用同一原开发服务的两个地址、共享原页面/登录/模块，不限制账号、不强制关闭下注；本机集成及此次行为对齐已实现和验证，生产交付尚未完成。当前实现、已关闭问题与验收边界以 [实现与对齐验收](../client/listener/LIVE_IMPLEMENTATION_REPORT.md) 为准；配套早期审计见 [全面审计](audits/LISTENER_ARBITRAGE_ISOLATED_BUILD_AUDIT_20261028.md)。不再采用早期候选中的后台准入开关、独立会话业务/预检包装或附加状态栏。

当前入口为原版 `http://localhost:5576/`、监听版 `http://localhost:5576/listener`（带末尾斜杠也可）。原 App、router routes/guards、appSession、fetchMatches、mainBetLoop 和补绑/补单/执行阶段均直接复用；构建内仅适配 hash history 和鉴权返回落点，套利扫描入口改为逐盘口通知集合。报价通知不额外加快周期扩展维护。原源码、构建/部署配置和旧 dist 保持不变；监听源码变更仍需独立构建。

模块化补充：监听实现现统一归 [监听模块](../client/listener/module/README.md)。两个入口都直接运行原 `client/web/src/main.ts`；监听启动、停止、周期定时和收尾均委托原方法。公共业务只有一份源码，后续改动由两版重新构建共同采用，不再维护另一份 bootstrap、鉴权函数或循环宿主。当前开发服务尚不自动重建监听 bundle。

## 1. 目标和取舍

用户的最高优先级是：现有用户继续使用原系统，原业务实现不得因新增监听套利受到破坏。新功能的正确性和隔离必须有证据，不能仅以“默认关闭”代替验证。

采用两份独立构建、两个明确入口：正式版继续使用原产物；监听试用版复用已有包、纯函数及通过副作用审查的组件，拥有自己的启动、监听、执行调度和停止流程。

第一版不在原网址增加自动分流，不修改原登录响应，不在扩展 TAB 增加可启用监听交易的选项，也不做会话内模式热切换。指定试用用户使用独立入口。后台变量只控制新入口的准入，不要求旧客户端理解新字段。

用户补充确认（2026-10-28）：“我确保同一个用户不会同时打开两个网页的。”本方案以同一用户不同时使用新旧网页为明确使用前提，不再要求实现跨网页/跨设备的分布式互斥，也不修改旧客户端接入新锁。该前提不取消新网页内部的任务去重、单执行器及会话收尾要求。

“不影响”需要分层验收：

| 层次 | 必须提供的证据 |
| --- | --- |
| 源码 | 原入口、旧业务实现、共享包和既有构建/发布配置相对实施前快照未变 |
| 正式产物 | 原 HTML、JS/CSS、资源路径、版本指针和缓存行为未被试用构建覆盖 |
| 普通用户运行 | 继续进入旧入口，无监听模块下载、初始化、额外请求或模式判断 |
| 会话与数据 | 试用版不清理正式会话、不迁移账号凭证、不改普通用户偏好或交易状态 |
| 共享服务 | 不新增生产采集器/matcher；试用流量有独立预算，不能以源码不变推导资源不受影响 |

保持正式产物不变可以验证其字节和路径；若连接共享后端、数据库、行情或场馆，仍须审查资源及账号隔离。文档不承诺共享基础设施不存在任何潜在故障。

## 2. 当前代码依据

- [HomeView](../client/web/src/views/HomeView.vue) 通过 `@/runtime/appSession` 导入 `mountAppSession`、`stopAppSession`；挂载时启动，卸载和退出时同步调用停止函数。
- [appSession](../client/web/src/runtime/appSession.ts) 负责账号/钱包准备、公共运行时、主循环、消息、余额刷新和清理；其中多项准备函数是私有函数，不能假设都已有可单独复用的公共入口。
- [matchStore](../client/web/src/stores/matchStore.ts) 调用 [mainBetLoop](../client/web/src/stores/match/mainBetLoop.ts)，经 [runArbBetRound](../client/web/src/stores/betting/runArbBetRound.ts) 和 [runA8ArbRound](../client/web/src/stores/betting/a8/runA8ArbRound.ts) 串行检测及执行每个盘口。100ms 是整轮结束后的等待，不是固定全量扫描周期。
- [App](../client/web/src/App.vue) 在组件初始化时就安装订单监控/同步。只替换 `appSession` 不会阻止这些能力启动。
- [默认 TS 配置](../client/web/tsconfig.app.json) 包含 `src/**/*.ts`、`src/**/*.vue`；[默认 Vite 配置](../client/web/vite.config.ts) 的测试也包含该目录。因此监听源码不能随意放进正式版的 `src` 后宣称没有构建影响。

## 3. 冻结范围和新增目录

初始实施只允许新增监听版文件；不重构或修改下列现有内容：

- `client/web/src/main.ts`、`App.vue`、`views/GateView.vue`、`views/HomeView.vue`、`router/`、`runtime/appSession.ts`、`runtime/sessionBoot.ts`。
- `client/web/src/stores/matchStore.ts`、`stores/match/mainBetLoop.ts`、`stores/betting/`、`stores/account/`、现有 store、模型和 bridge 实现。
- `client/packages/`、`packages/shared/`、`packages/api-contract/`、Chrome 扩展及现有平台实现。
- 原登录/鉴权 API、用户偏好协议、数据库结构和生产配置。
- 根 `package.json`、lock、Turbo 配置，以及正式版 Vite/TS 配置、构建脚本、工作流和发布脚本。

拟新增 `client/listener/`，位于正式版 `src`、`vite`、`scripts` 之外，初始阶段不新建 workspace、不改 lock。该路径只是候选归属，不代表已获现行边界门禁或发布分类批准；见审计 A03。

拟分为：

```text
client/listener/
  entry/                 # 独立 HTML、bootstrap、路由与宿主
  runtime/               # 新会话生命周期、监听和调度
  replay/                # 无网络行情回放和只读检测
  build/                 # 专用 Vite/TS/测试配置与构建入口
  tests/                 # 监听版行为及隔离验收
```

所有新增 Vite 中间件/插件仍采用严格类型的独立 TS 模块。复用配置或插件前必须检查其写文件、复制资源和清理目录的副作用；不得直接执行默认前端构建来生成试用产物。

## 4. 构建与运行时绑定

| 项目 | 正式版 | 监听版 |
| --- | --- | --- |
| 入口、配置、生命周期 | 全部保持现有实现 | 新增专用入口和宿主 |
| 套利调度 | 原主循环 | 盘口监听、去重队列和单执行器 |
| 计算和执行能力 | 现有实现 | 按阶段只读复用或显式调用原函数 |
| 输出 | 现有正式版本目录 | 候选 `output/listener-preview/<build-id>/`，与正式目录不重叠 |
| 发布/回滚 | 原流程不变 | 另行设计专用流程；不调用正式前端发布脚本 |

原始设想是只在监听构建中精确映射 `@/runtime/appSession` 到新模块，使已有界面调用新宿主。此机制可用于构建验证，但不是交易安全证明：原 `App` 有提前启动的能力，原 `HomeView` 的同步退出接口不能等待在途执行。

审计后的约束是：S0/S1 使用新增的只读 bootstrap/root；S2 使用可控制初始化、路由离开和异步退出的新宿主。可以复用原展示组件；不得为了少写新页面而加载整个原 `main.ts`、`App.vue` 或具有未审查副作用的原页面。若最终保留会话入口映射，必须证明它与新宿主共同满足上述要求。

专用映射必须精确匹配、先于通用 `@` 解析；Vite、TS 和测试解析结果一致。不得宽泛替换 store 或 `stores/betting`、不得把同一 store/bridge 加载成两个模块实例、不得通过运行时改写旧方法实现分流。以解析后的模块图验收，不能只搜索打包文本。

正式构建不引用监听目录。监听构建可能因复用 `matchStore` 而静态包含原循环模块；验收要求是原循环不被调用或启动，不能错误要求“任何旧循环代码均不得出现在监听包”。

## 5. 分阶段交付

### S0：本机离线回放

- 新增独立入口与只读报价 bridge，使用脱敏、可复现的行情样本。
- 不连接生产 API/场馆，不加载钱包、账号执行、采集器、完整 `App`、消息发送或订单监控。
- 调用现有检测函数，记录触发范围、选腿、利润、失效原因和延迟；对照同一报价快照的原检测结果。
- 禁止调用 `prepareArbAttempt`、`executeArbBet`、补单和任何带保存/通知副作用的盯盘 sink。
- 不要求采样次数与原循环完全相同：事件驱动会改变检测时机，但相同输入快照的计算结果必须一致。

这是当前允许进入实现的最小范围；仍需新增代码对应的边界、类型和行为验证。本次文档工作没有实施 S0。

### S1：独立实时只读预览

S0 通过后，再验证鉴权、路由、资源、浏览器存储、数据来源和请求预算。新服务端准入仅作用于监听入口，必须依据服务端验证的用户身份，不能信任前端提交的 userId。

S1 不直接调用 `bootSessionRuntime()` 或原 collector 启动链来取得行情；这些链路可能上报赛事、盘口和计时。先证明行情读取没有生产写入。请求策略按 API action/场馆操作定义，不能把 POST 全部视为写、也不能把“没调用新下单器”视为零副作用。

允许的数据来源、最大连接数、请求速率、超时和熔断阈值，必须在接入前给出具体验收值；本方案不猜测生产容量。

### S2：限定账号真实执行

仅在 S1 和审计全部交易阻断项关闭后开放：

- 由后台独立名单允许，默认只读；启用监听入口不等于授权交易。
- 使用专用试用用户和独占的场馆账号，遵守原账号 owner 隔离，不跨 profile 复制凭证。
- 先保持同一监听运行时最多一笔自动套利执行；检测可继续合并更新，执行队列有上限。
- 同一用户不同时使用新旧网页由用户保证；本次不实现跨网页/跨设备互斥。新运行时仍须防止重复初始化、重复任务和同盘口并发执行。
- 复用原完整执行器前，必须证明在途执行、退出和会话失效的处理契约。若契约无法满足，S2 保持阻断；允许另写新编排复用公开阶段函数，但不能宣称只在阶段外加校验就覆盖了阶段内部的顺序下单及重试。
- 不更改 PM FOK/GTC、普通/LOS/9999、下注排序、金额、利润、限红、重试和补单等业务规则；启用哪些组合须逐项验证，未验证组合在试用版明确不可执行，不修改原偏好来绕过。

## 6. 监听与检测合同

1. 监视单位为“用户/会话 + 比赛 + 合并盘口”；记录当前盘口对象/来源版本，不能仅凭可复用的 betId 保留旧引用。
2. 读取关联选项的有效报价与锁盘；监测结构替换、报价规则/PM tick 元数据、平台范围、利润参数、余额及账号状态变化。赛事状态、折叠禁下和时间到期条件亦需覆盖。
3. 重复相同值、展示闪烁和无关 store mutation 不触发交易；检测中不能随机金额、选号、占位或写回用户配置，避免自激循环。
4. 使用有最大等待时间的合并队列，不能只用不断重置的尾部 debounce；持续行情下也必须按预算处理。
5. 执行前从当前列表取得有效盘口，重新读取报价并调用原准入规则；排队报价不作为已通过预检的依据。快照是各来源最新可用值，不宣称跨平台时间同步。
6. 同一盘口执行中最多保留一个“需重检”标记。完成后根据当前报价、原账号门槛和明确的重试/冷却规则重检，不能因机会持续成立而无界连发，也不能永远只检测首次跨阈值。
7. 低频兜底只用于漏通知、时间条件和恢复；周期、报价陈旧阈值、重试预算在 S1/S2 验收前明确，不从缓存的一小时清理策略推导可交易报价有效期。

## 7. 生命周期、依赖和维护

新宿主的设计状态为 `NEW → AUTHORIZED → INITIALIZING → OBSERVING`；仅 S2 验收后允许进入 `EXECUTING`，停止进入 `DRAINING → STOPPED`，异常进入 `BLOCKED`。重新初始化必须幂等；不得先启动原循环再停止它。

只读阶段不装载生产交易能力。交易阶段需逐项记录以下责任：

| 能力 | 必须明确的责任 |
| --- | --- |
| 钱包、signer、PM/PF 路由 | 准入后初始化，失败不自动回退原循环，不静默迁移/保存试用凭证 |
| 收集器、订单监控、消息 | 每个模块唯一启停者；原 `App` 已安装的能力不能重复安装 |
| 赛事/初赔/赔率缓存 | 复用原 store 方法；实现列表失败门控、缓存清理与对象替换处理 |
| 补绑、待确认原单、补单 | 明确执行前后顺序，保留不依赖买入/补单开关的观察语义 |
| 账号 `active` 与余额 | 执行中不得被周期任务提前清理；收尾后按原规则恢复 |
| 自动开启、EV、提前锁利及旁路通知 | 逐项确认；不能因换宿主丢失或未经授权提前启用 |
| 退出、路由离开、重连 | 停止新任务，处理在途结果后再允许重置/换用户；强制失效另有测试 |

交易宿主不能简单照搬原主循环去掉套利段：每项维护行为都要对照源代码、异常路径和开关语义验证。原周期常量仅作参考，改变试用调度须显式记录。

## 8. 入口、鉴权、存储与后台名单

S0 使用本机离线入口，无生产鉴权和后台改动。S1/S2 的发布拓扑在审计关闭前不确定具体域名或线上路径。

- 同源子路径不会隔离 Cookie、localStorage、IndexedDB 和部分跨标签页通知；不能称为浏览器安全边界。独立路由必须配置相应 router history base、Vite base、懒加载和静态回退。
- 独立 origin 不能假设继承现有 `__Host` Cookie 或自动满足 Origin/CSRF；不得通过关闭这些校验接入。
- 初期在线试用需专用浏览器配置文件和试用账号，并验证 Cookie、钱包/扩展保留会话、存储键和锁事件的影响。同一用户不并行运行新旧网页按上述使用前提执行，不另加跨设备交易锁。
- 后台名单、全局开关、只读/执行能力及配置版本仅由新服务端入口管理。缺失、过期、拒绝或无法核实均保持试用版停止/只读，不启动原循环。
- 不在旧 `Client_GetUserInfo` 中添加模式字段，不把配置写进原 `Setting`、`Extensions`，不自动重定向正式用户。
- 名单只控制准入；已发送订单不会因撤名单自动取消。撤销的检测时机、停止新任务与在途收尾分别验收。

## 9. 构建、验证、发布与回滚

正式版原产物继续使用，不要求重新构建正式版来证明试用版可运行。若要证明默认构建不被新增文件影响，另在隔离输出和构建缓存中运行验证，不能覆盖正式目录。

专用构建开始前检查解析后的绝对输出/缓存路径，拒绝等于正式目录、其祖先或通过软链接指向正式目录的路径。声明独立 `outDir` 不够，还要审查 prebuild、插件、生成文件、TS build info 和复制步骤。不直接复用 `npm run app:build` 或 `client/web` 默认 prebuild。

当前部署分类不认识 `client/listener/`，未知路径会保守选择 full；因此不能将“文件放在新目录”视为自动发布隔离。在独立 CI/制品/发布目标审查完成前，不得把监听源码推入会自动执行现网发布的流程。不得为省检查而全局忽略目录或降低现有门禁。

监听版必须有独立的构建身份、源码/依赖指纹、模块解析清单、资源 base、验收报告、发布锁、版本指针、回滚和保留策略。不使用现有 `release-frontend.sh` 激活监听产物；该脚本切换正式 `client/web/dist`。

不启动额外生产 backend 全栈、collector、matcher 或共用生产 storage 的后台进程来“隔离试用”。如需新的准入服务/静态托管，只增加明确的新入口、预算和健康检查；任何共享部署配置改动另行审查。

## 10. 验收矩阵与阶段门

| 编号 | 必须验收的行为 | 阶段 |
| --- | --- | --- |
| V01 | 实施前工作区快照、旧源码/配置未变；既有未提交改动不被计为本功能改动 | 全部 |
| V02 | 正式 HTML、资源、路由、发布指针未变；试用构建失败也不清理正式目录 | 构建/发布 |
| V03 | 正式模块图不引用监听源码；监听解析映射正确且 Vue/Pinia/store 单实例 | 构建 |
| V04 | 回放相同报价计算一致，锁盘/列表替换/规则变化/持续行情/时间恢复正确 | S0/S1 |
| V05 | 只读入口无下注、补单、卖出、账号配置保存、行情上报或外部通知；不能只查一个执行入口 | S0/S1 |
| V06 | 拒绝名单/会话过期/模块失败不启动交易或原循环；普通入口请求与原版一致 | S1/S2 |
