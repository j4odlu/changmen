# Matcher 统一比赛结果方案

[changmen 扩展] 2026-10-25 按用户确认的原有业务规则修订。此前审计见[审计报告](audits/MATCH_PUBLICATION_CONSISTENCY_AUDIT_20261019.md)。

## 原则

matcher 负责匹配和更新比赛，changmen 按现有规则判定比赛是否结束。未结束的比赛下发到客户端；已结束的比赛不下发。用户页面和 matcher 当前列表读取同一份 client_matches 记录，不再各自依据另一次平台快照删比赛。

不增加“是否展示”状态，不保存整场比赛副本。删除此前添加的 current_result 字段及相关读写，不新增替代字段。

```text
平台采集 → matcher 匹配、刷新盘口、执行原有结束判定 → client_matches
                                                    ├→ 用户接口
                                                    └→ matcher 页面
```

## 现有字段的职责

| 字段 | 保存内容 |
| --- | --- |
| matchs | 比赛与各平台场次的完整匹配关联 |
| bets、reverse | matcher 算好的盘口、锁定状态及主客方向 |
| ended_at | changmen 判定结束后的时间；结束只改变生命周期，关联保留 |
| pm_sport | 原有独立更新的 PM 比分与状态 |

两端共用现有 RDS 快照与缓存版本机制，直接读取这些字段。既有 RAY 异常保护沿用同一过滤函数，不借删除字段放开风险比赛，也不新增结束条件。

## 场馆退出采集时的处理

| 情况 | 处理 |
| --- | --- |
| 已有比赛只剩一个场馆 | 继续刷新仍在场馆的盘口，保留其余场馆关联并锁定旧盘口 |
| 全部场馆退出，尚未触发现有结束规则 | 保留比赛，全部旧盘口锁定，不另设隐藏状态 |
| 现有规则判定结束，或人工强制结束 | 写结束状态，两端当前列表不再包含该比赛，原关联保留 |
| 场馆恢复且比赛未结束 | 使用原身份和新采集的原生盘口恢复更新 |

OB/RAY 退出采集范围不表示匹配关系错误，也不单独替代 PM 或 changmen 的结束判定。旧盘口行与盘口 ID 保留，缺席场馆的选项 ID 清空、赔率为零并设为 Locked，复用现有 A8 前端锁盘行为；来源恢复后重新填入原生选项 ID。

新比赛的两馆匹配门槛不变，已有单馆比赛不能因不再满足新场门槛而停止刷新。真实结束、PM 终态和来源缺失后的现有结束兜底均不改动。

## 三步实施，每步完成都能停

1. **matcher 把最终结果写回原字段。** 补齐已有单馆、全部场馆缺席时的盘口刷新与锁定，保留匹配关联。比赛、盘口与结束状态沿用同一事务写入，提交后刷新缓存。必需数据读取失败不当成空数据写库。
2. **两端直接读取同一份记录。** 用户接口与 matcher 当前列表使用共用 RDS 快照，去掉页面额外的两馆门槛和平台存活过滤。恢复比赛时先锁定旧盘口，再从场馆刷新。无需新增结果字段。
3. **部署后验收。** 核对首轮 matcher 写入、用户 API 和 matcher 当前列表的比赛 ID、关联、盘口引用与方向。结束赛事不下发；未结束的锁盘赛事两端一致。允许既有合场周期和页面轮询带来的更新时间差。

前两步分别通过所属模块回归后均可暂停；第三步不扩展为新推送、状态机或持续监控工程。改动后的验证结果须重新确认，撤销方案之前的检查记录不代替当前实现验收。

## 2026-10-25 追加审计与修复

此前完整回归未覆盖以下两个结束判定场景，已使用隔离 PostgreSQL 与实际合场函数复现。用户确认后修复，不增加字段或结束规则，没有写生产数据。

1. 已有单馆比赛曾在 End 阶段之后才进入输出，可能满足原有结束规则却继续下发。现改为数据库里的全部未结束 changmen 比赛先进入结束检查集合，再统一判定；不依赖本轮是否重新匹配成功。
2. 盘口投影曾临时移除缺席 PM 的关联，导致有 PM 映射的比赛错误进入其他场馆的结束分支。现先恢复完整匹配关联，再执行同一个 End 阶段。PM 数据缺席时仍使用原映射；PM 确认结束时正常结束。

用户明确取消整场比赛的人工主客对调功能。已删除“主客对调（翻锁）”按钮、事件处理、swap-gb API、matcher 处理函数及数据库导出与实现。原主客锁、自动平台方向投影及单平台方向纠正保持原有职责；本次不翻转已有比赛数据。

回归覆盖单馆比赛原有结束规则、有 PM 映射但没有 PM 快照、PM 真实结束，以及既有结束来源不重新建场。功能删除后的 33 项针对性检查、隔离 PostgreSQL 的 15 项原有场景及 3 项补充验证均通过；`npm run check:change` 完整通过，源码稳定检查通过，涵盖后端、前端及生产构建。原问题复现记录保存在本机 output/matcher-reaudit-20261025/post-removal-audit-findings.json，当前验证记录为同目录 swap-removed-check.log、swap-removed-verdict.json、swap-removed-phase2-postgres.log 和 end-fixes-swap-removed-postgres.json。本次未 push、未部署、未重启本机服务。
