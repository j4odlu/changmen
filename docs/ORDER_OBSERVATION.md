# 订单旁路观察系统

[changmen 扩展] 此模块只记录现有动作与结果。事件、诊断结论、上传成功与否都不得作为下注、重试、补单、取消、余额刷新或超时策略的输入。

## 标识与兼容

- `attemptId`：一个业务提交周期，可包含多次预检；即时重试和新的补单执行创建新 ID。恢复原单确认沿用旧 ID。
- `queueId`：补单任务的一次生命周期；业务 Map 仍按 betId 索引，同 betId 覆盖记录 queue_replaced，不增加业务队列项。
- `anchorAttemptId` / `anchorOrderId`：只记录当时已知关联；有锚标识不等于锚腿已确认成交。没有证据不补造订单 ID。
- `eventId`：首次入队生成，上传重试不更换。服务端按用户/eventId 去重，只确认内容一致的已保存事件。
- 旧持久化任务没有标识时保留缺失；不能把恢复时间当成原提交时间。LoseOrder 和后台确认任务保存观察元数据。

## 事件与可靠性

预检、适配器提交、返回、场馆观察、补单生命周期、决策及绑定回执分别记录。submission_started 表示进入适配器调用，不证明 HTTP POST 已送达；adapter_failed 不证明场馆未成交。

字段采用白名单，不上传 token、私钥、请求/响应全文或用户配置。金额、汇率与比例来自当时对象快照；未取得实际成交数量时，不推算部分成交。

同步路径只生成小型事件并放入内存。上传和 sessionStorage 写入由独立任务执行。队列最多 512 条普通事件、32 条缺口记录，每批最多 32 条，失败退避最高 60 秒。容量不足或存储失败产生 transport_gap。sessionStorage 可支持同标签页刷新；关闭标签页、崩溃或存储不可用时仍可能丢失，不能承诺完整交付。

上传使用独立传输：10 秒超时，不触发通用 API 的 token 刷新、清会话、成功提示或延迟采样。事件绑定原用户；当前用户不匹配或登录切换时暂停发送，服务端再次校验认证用户。

## 服务端与展示

保留 Client_SaveUserLog 及原日志形状。专用 title `[changmen] OrderObservation/v1` 的批次写独立 order_observations 表，普通日志仍按原路径处理。user_id 从认证上下文取，不信任客户端任意指定归属。

诊断接口新增 observation 字段，mode 固定为 shadow。新表不可用时保留原诊断，返回 unavailable。新结果不替换现有规则，不发起额外场馆请求。客户端事件显示 client_reported，不能冒充独立场馆对账证据。

客户端发生时间与服务端接收时间分别保留。尝试内按 sequence 检查缺口，时间不作为唯一因果依据。序号冲突、提交结果未知、缺少确认/绑定、日志截断明确提示。PM timeout_policy 只表示原业务策略处理，绝不冒充官方拒单回执。

未找到精确 orderId 的场馆订单时，现有成交/拒单判定只记录为 orchestration_result（编排结果）；它与 timeout_policy、仍待确认的 timeout 均不能消除“缺少场馆确认”提示。transport_gap 是缺口元数据，不参加业务事件序号冲突判断。

## 发布顺序

1. 先在目标环境执行 `server/backend/db/migrations/20261002_order_observations.sql`，它只创建观察表和索引，不改 orders、players 或业务状态。
2. 发布服务端接收与查询代码，再发布客户端。反向发布会让旧服务端把专用批次写成普通日志且无法返回事件确认。
3. 先保持 shadow 展示，用脱敏真实案例核验。原单策略、POST 次数和参数、补单队列覆盖与取消、绑定与余额刷新必须与改动前一致。
4. 暂不自动切换新诊断为主结论，也不修改原业务流程。移除客户端 startOrderObservation 调用可停止新增事件；观察表可保留用于追溯。

本次离线测试覆盖上传失败、存储故障、容量溢出、用户切换、重复/乱序/缺失事件、超时策略、元数据恢复及下注次数/预检闸门。真实场馆对账、生产查询耗时和页面视觉验收仍需在发布环境验证。

## 实时进度与后台共用事实

[changmen 扩展] 已入观察队列的同一 eventId 会同时进入只读本地事实视图和异步上传队列。上传回执不会删除本地视图；刷新只恢复尚在上传队列中的事件，不补造已上传历史。两处共用 order_observation_view 的事件名称、证据来源解释及尝试内序号排序。本地视图保留最近 512 条；用户归属与非零 Link 校验后才展示，不能把所有 Link=0 的事件混到一单。

实时面板优先展示这些执行记录；原有编排消息作为补充详情，无事件时明确标记为编排记录。业务进度、倒计时、终态移除、activeBetRunStore 的状态及补单读取方式均保留。后台展示的是已接收事件，本地即时展示与后台可能存在上传延迟或缺口，不承诺每一时刻内容完全一致。

补绑沿用原 API、队列、去重、次数及超时条件，只追加原尝试的成功/失败/未知回执。事实视图与共享展示函数不作为任何业务决策的输入。

没有方向字段的绑定回执，只在原用户、同一尝试或队列的方向唯一时归属到对应腿；无法归属的事件单列展示，不按平台或时间猜测。已发生本地历史裁剪时提示截断，不将缓存视图当成完整历史。
