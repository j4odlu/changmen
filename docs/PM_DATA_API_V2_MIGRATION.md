# Polymarket Data API v2 迁移

实施日期：2026-10-05。代码已迁移；本次未部署生产，也未写入真实账户订单。

## 范围与契约

- `pmActivityV2.ts` 请求公开 `/v2/activity`，解包 `data` / `pagination`，将 snake_case 字段映射为既有 `PolymarketActivityTradeRow`。
- `token_id` 映射为 `asset`；金额、份额、价格只接受有限 JSON number；缺失/null 保留为不可用。Combo 行不参与单市场成本核对。
- `pmActivity.ts` / `pmFee.ts` 沿用成本算法。每个目标交易哈希都必须在指定 condition/token 中找到有效买入金额；缺失字段、其他市场同哈希、无效金额不能形成部分成本。
- 单笔/批量以最早买单时间向前扩展 900 秒作为下界，上界固定为本轮查询时间加 60 秒；不以创建后 15 分钟限制成交，因为 GTC/部分成交的链上结算可能明显晚于创建时间。缺失时间时不擅自截断下界。
- 页大小默认 200，上限 1000。每次查询默认最多 10 页 / 10000 行 / 15 秒；可配置但硬上限为 20 页 / 20000 行 / 30 秒。查询达到预算且未完成、游标重复或任一页失败时丢弃全部结果，记录失败，调用方保留已有成本或沿用公式回退。
- 分页始终携带 user、type、side、start/end 和排序，使用不透明 next_cursor；不发送 offset。
- 429/503 或对应暂时不可用错误最多重试两次；遵循 Retry-After，等待超过总预算则停止。直连、插件及 VPS 保留错误状态和响应元数据；VPS 仅转发 retry-after / x-trace-id，不转发 Cookie/授权头。
- 不自动回退旧版 API。官方迁移指南宣布 v1 于 2026-10-24 退役。

## 验证

- 官方示例公开钱包 `0x983eedfbd75803602e4a6e6ea9aab6dc6b9c6748`：旧版 200 条 BUY 与 v2 的 size / price / usdc_size / condition / token / tx 对齐，金额与价格无差异；其中 38 条有可识别的手续费。
- `pmActivityV2.live.test.ts` 通过真实网络调用迁移代码，每页 37 条，覆盖上述 200 条旧版记录并验证真实游标分页。此探针只读，不需要钱包凭据，也不连接数据库。
- 单测覆盖响应格式、null/缺失/非有限金额、combo 排除、跨页多哈希匹配、重复成交、错误/截断丢弃、限流重试、总超时、批量时间窗和重复补费。
- 三种传输模式已通过模拟通道契约测试。尚未在生产登录会话中对插件/VPS 做端到端验收，也未核对真实业务账户的链上资金流水。
- 已通过：`npm test`（13 项 workspace 任务）、`npm run test:checks`、生产 `npm run app:build`（含 vue-tsc）、针对性前端 81 项测试、后端代理/handler 18 项测试，以及公开接口 live smoke。构建存在现有大 chunk 提示，未出现构建错误。

## 2026-10-05 复查与修复

以下五项均先补回归测试复现失败，再修复：

1. 创建后 900 秒的查询上界漏掉晚成交挂单：改为本轮读取时间上界，保留既有下界和分页预算。
2. 无交易哈希的近似匹配允许缺失 condition/token 或时间字段：要求已指定的过滤字段全部匹配，指定成交时间时必须有有效行时间。
3. 无效交易哈希被过滤掉，或全部无效时降回近似匹配：只要传入非空哈希列表就走精确匹配，任一哈希无效则拒绝。
4. 多笔成交现金逐条四舍五入再汇总，及单笔手续费先五位再四位的二次舍入，产生尾差：保留现金/手续费原始精度，最终输出再取四位；去重键也使用原始现金和价格。
5. 同一 tx/token 的聚合 activity 成本重复覆盖较小订单：应用前核对订单成交份额与 activity 总份额，仅允许 0.0001 份舍入误差；不符则沿用已存成本/既有公式回退。

该保护不会把聚合交易金额擅自拆分给订单。复杂同 tx 多订单的精确费用分摊仍需 CLOB 成交腿/链上流水佐证。

复查修复后的完整前端测试：380 个文件、2470 项测试通过；vue-tsc 通过。默认跳过的 1 项公开网络探针已单独执行并通过。边界/adapter/目录检查通过；回归测试覆盖上述五类问题。

## 发布安排

本次范围为 Data API v2 接口迁移。必要回归测试和生产构建已通过，可以按现有流程发布；真实账户全面对账、性能专项及浏览器运行时排障不作为本次发布前置项。发布后只读检查现有订单刷新、费用显示和 v2 失败日志。

复跑公开接口对账（PowerShell，仓库根目录）：

```powershell
$env:PM_DATA_V2_LIVE = '1'
npm exec --workspace=@changmen/web -- vitest run pmActivityV2.live
Remove-Item Env:PM_DATA_V2_LIVE
```

该探针依赖退役前的旧版服务，仅用于迁移期对账；旧版退役后不作为日常 CI 门槛。默认测试跳过网络探针。

## 上线与回退

按仓库现有生产部署流程发布前端与后端；后端新增响应头是可选字段，兼容旧客户端。无需数据库迁移、历史订单批量改写或更新 Chrome 扩展包。

发布后在现有账号上分别验证直连、插件和 VPS 查询，观察 `拉取 /v2/activity 失败` 日志、查询耗时、成本补全及多笔成交。首轮应只读核对已存在的订单及官网记录，发现不能解释的金额差异时暂停上线。

旧版退役前可回退前一个前端版本；退役后不能把 v1 当作可用的长期回退方案，需保持已存成本/公式回退并修复 v2 读取。请求失败不会用半截 activity 金额覆盖订单。
