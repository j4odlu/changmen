## 1. 本次实施范围

仅调整浏览器 `marketQuoteHub` 所管理的 **PM-M 官方直连连接**：

| 时机 | 现在的处理 |
| --- | --- |
| 建立连接，已有资产 | 一次 `type: market` 发送当前消费者资产并集，请求初始 book |
| 预连接时没有资产 | 不发送空订阅；首次出现资产时发送初始 market 帧 |
| 连接运行中新增资产 | 只发送新增差集，`operation: subscribe`，保留自定义 BBO 事件 |
| 连接运行中移除资产 | 只发送已无消费者使用的资产，`operation: unsubscribe` |
| 同集合、不同顺序、重复 ID 或同集合 force 登记 | 不重复发送官方订阅 |
| 多消费者共享同一资产 | 最后一个消费者退出该资产时才退订 |
| 连接断开期间资产变化 | 仅保留最新消费者集合；重连后按最新并集发送一次初始 market 帧 |
| 官方/CHANGMEN 来源切换 | 按本次实际 socket 来源处理；转发继续原整组消息，返回官方时重新初始化 |

本次不改 VPS、独立体育板 `sportQuoteHub`、价格解析、fo 合并、报价缓冲、FOK/GTC 执行或 SDK 版本；不新增连接、HTTP 请求、恢复队列或交易抑制。

官方连接的判定由 transport 在 `onOpen` 中传递创建该 socket 时的来源，不根据可能已改变的页面偏好猜测。官方已发送集合只属于当前连接，断线或停止即清理。

`force` 保留在消费者登记接口中；对官方连接，重连后的全量订阅由真正的 onOpen 完成，同集合 force 不再产生重复帧。对转发路径，原 force 行为保留。

### 4.4 暂缓 C：修复报价先后判断

用户已要求本次先不处理；以下为保留设计，当前不执行。本批的已知风险继续记录，不因此认定全链路已无时序问题。

#### 已核对的代码事实

[liveQuoteState.ts](../client/packages/venue-browser/polymarket/liveQuoteState.ts) 用同一个 token 时间记录保存两类时间：预检修正调用 `notePolymarketLiveBookQuote` 时默认写 `Date.now()`，WS 调用 `shouldApplyPolymarketWsQuote` 时用消息中的交易所 timestamp 与该记录比较。两种时间来自不同机器，不能用大小直接判断报价先后。

例如本机快 5 秒：预检修正写入本机 10:00:05，随后到达的新 WS 标记交易所 10:00:01，会被误认为旧行情。当前无 timestamp 分支的 2 秒保护窗同样受这个混用状态影响。该辅助状态被主行情 hub 和独立体育 hub 共用，还需要验证来源及生命周期隔离，不能仅替换一次 `Date.now()`。

预检获取 book 已保存交易所 `bookTimestamp`；`bookFetchedAt` 则是本地完成时间，并参与现有优化 FOK 判断，不能把它改成交易所时间。当前 `PolymarketPriceAboveDetectionError` 只有实际卖价和检测限价，没有请求开始时的报价版本或连接身份。HTTP 回来后能否更新显示，不能仅凭“返回时间晚”或“价格更高”决定。

以上是代码事实和待修复风险，不是截图中那次失败的完整归因。

#### 实施步骤与边界

1. **先建立失败回归。** 通过实际 hub、预检修正入口与报价缓存复现本机快/慢 5 秒，以及 HTTP 发起后新 WS 先到、旧 HTTP 后到；先证明错误，再改运行逻辑。
2. **追踪全部调用链。** 从 book 请求开始、返回、构造异常到纠偏 catch，核对 [fok/preflight.ts](../client/packages/venue-browser/polymarket/fok/preflight.ts)、[fok/bet.ts](../client/packages/venue-browser/polymarket/fok/bet.ts)、[pmPriceError.ts](../client/packages/venue-browser/polymarket/pmPriceError.ts)、[quotes/pmTokenQuote.ts](../client/packages/venue-browser/polymarket/quotes/pmTokenQuote.ts)。确认预检与执行复用、FOK/GTC 实际经过哪些入口，再确定最少附加字段，禁止重复请求 book。
3. **拆开两种时序。** 交易所时间仅在时间来源、单位及可比范围明确时比较；本地用与墙钟校时无关的接收顺序/版本记录状态变化。相同 timestamp 的多条事件可能都有效，不能简单改为只接受严格更大时间。缺 timestamp 也要有明确规则，不能继续靠混用时间的固定保护窗误挡新行情。
4. **约束 HTTP 回写。** 请求开始时关联同一 token 的当前报价版本及所属行情会话；返回时结合可信源时间与期间更新判断是否仍可写当前显示。无法证明较新的迟到结果，不覆盖请求期间已经接受的新报价。保留该 HTTP 结果原有的预检/执行判断作用；显示更新被拒绝不等于允许下单。真正可用的后续请求仍应能修正当前价。
5. **定义清理与隔离。** 明确断线重连、来源切换、退订后重新加入及退出时哪些状态失效；旧会话 HTTP 不得污染新会话。主行情与独立体育的共享辅助入口不能互相钉住时间。直连优先，转发与独立体育保留原业务并覆盖兼容回归；如果公共接口需要扩展，单独列出影响，禁止从比分字段推断来源。
6. **复核交易语义并跑所属模块门禁。** 不改变当前尝试冻结的 cap、金额、缓冲、FOK/GTC 提交、确认或拒单规则。新尝试可读取已接受的新价；现有尝试继续按原冻结条件检查。核对是否有其他写入入口绕过顺序判定，再完成类型/构建及业务回归。

#### 必需验收场景

| 场景 | 预期结果 |
| --- | --- |
| 本机快/慢 5 秒，修正后到达更新 WS | 新行情按实际顺序更新，不因时钟偏差丢失；有效降价也能接受 |
| 同一行情流乱序、同 timestamp 多事件、缺 timestamp | 可证明旧的丢弃；同时间有效变化不一刀切丢弃；缺时间规则有独立回归 |
| HTTP 请求期间 WS 更新到 0.34，旧 book=0.35 后返回 | 旧结果不覆盖当前 0.34；原尝试的价差拦截仍保留 |
| 没有期间新行情，后续有效 book 修正当前价格 | 可正常更新显示，不把所有 HTTP 修正永久禁用 |
| 两个 HTTP 请求交错返回 | 较早结果不覆盖已经接受的较新结果；读价和拒单判断分别验证 |
| 重连、切换来源、移除再订阅或退出后旧 HTTP 返回 | 按生命周期判定失效，不污染新的当前报价 |
| clean、直连目录刷新、主列表与独立体育分别更新 | 不恢复 Index 旧价；已修复的页面范围隔离和快照行为保持 |
| FOK/GTC、预检与执行复用、冻结 cap/金额 | 原有交易判断和参数保持，更新显示不放行原本应拦截的订单 |
