[changmen 扩展] 本节为代码与既有证据复核后的后续验收方案，优先于下方历史快路径设计。**当前不能启用实际本地预检：只改文档，没有修改运行代码、开关、用户配置或发布。** 以下标为“建议”的数值是待实现、待实测的工程验收目标，不是已实现配置、PM 官方要求或收益保证。

### 当前已经有的与仍然缺少的

- 已有：PM-M 原始流 → 独立订单簿服务/Worker → 动态旁路和深度租约。默认关闭，实际 `runOptimizedFokPreflight` 仍无条件调用 `tasks.market()`；报告明确 `activeSupported=false`。现有两个 UI 开关都不能授权实际使用本地结果。
- 缺少执行级只读接口：当前 `readDepth` 默认 20 档、最多 50 档，可能截断；其 5 秒读超时由 reconcile 检测，不适合交易等待。需要完整相关深度、原始时间、session/epoch/generation/revision、已处理输入位置、元数据身份/版本及失效原因的不可变读取契约。不能把展示视图当执行簿，不能复制回主线程后重新打时间冒充新鲜数据。
- 缺少等价计算适配：`resolvePolymarketExecutableBuy` 当前把 HTTP 读取与可执行价格计算连在一起。需要为动态分支提供可复用计算入口，覆盖冻结限价、金额、份数、精度/取整、tick、最小份数、深度缓冲和返回值形状；保证相同输入与原 HTTP 算法完全一致。不得重写经典算法或改变双腿顺序、单次提交、确认和补单。
- 缺少执行级元数据缓存：当前 `version/tick/minSize/negRisk/market` 来自旁路 HTTP probe，随消费者卸载被清理。执行不能依赖“诊断对照开着”，更不能只凭 WS 深度猜签单参数。需由动态消费者明确管理可信元数据来源、身份匹配、过期/tick 变化失效；缺失直接走原 HTTP。本地订单簿核心仍不依赖账号、HTTP 预检或签名器。
- 缺少实际来源选择/回退/竞态保护：包括有界 Worker 往返、单次 HTTP 回退、迟到响应丢弃、读期间关闭/切路由/失效、后台暂停后按真实年龄重新判断，以及当次尝试绑定。当前旁路代码不等于已实现这些保证。
- 缺少实际尝试口径的覆盖、端到端耗时与生产设备证据：已有 30 分钟/1,106,280 帧旁路验证，274 次时间对齐比较相等、可比差异 0；110 次未对齐和 13 次歧义不算一致。固定资产动态可用采样为 37.29%/30.37%，不是实际预检命中率。当前 `localReadMs` 明确不含完整执行价格校验，不能据此宣传预检加速或双腿成交提升。

### 实际分支与 HTTP 回退契约（尚未实现）

1. 仅对显式选择动态复核、已有合格官方 PM-M 与直连 HTTP/提交、有效登录及账号的 **FOK 新尝试**，再检查独立的“实际使用本地订单簿”授权；该授权将来另行设计，默认关闭，现有两旁路开关不自动升级。经典/default/非法模式、GTC、VPS、中转与未支持类型均保持原入口，经典不增加读簿等待或新的拒单门控。
2. 候选已被服务接纳且有合格快照时，发起一次有界读取。建议端到端读取及本地计算预算 20ms（从主线程发起算，含排队/传输）；确定不可用立即 HTTP，不等新快照、不在预检现场补订阅或重连。当前 5 秒展示超时不得复用。后台定时器不保证 20ms 准时触发，因此必须在回复和恢复执行时再核验实际 elapsed，超时返回也不可采用。
3. 接受结果前同时校验资产/市场、session/epoch/generation、服务健康、输入处理位置与失效状态、元数据和原始年龄。使用现有保守上限作为起点：簿本地接收年龄 ≤1,000ms、完整快照年龄 ≤60,000ms、元数据年龄 ≤60,000ms、源时间不早于当前墙钟 5,000ms且不超前 1,000ms。上述都不是已证明适合真实交易的阈值；需按实际延迟/报价风险分层验证，可收紧，不能为命中率放宽。源时钟异常或无法解释的间隙直接不可用，PONG/BBO/读取不刷新深度年龄。
4. 初批建议采用“本地只提供肯定结果”：合格且通过原等价深度/价格算法时采用本地；本地算出深度不足/不满足价格也交原 HTTP 再判，避免新引入本地误拒单。这不允许绕过原有锁盘、赛事终局、最新不利报价、钱包/凭据保护；这些交易保护仍按原流程拒绝或取消，不属于数据故障回退。
5. 本地不可用、错误或超时 → **只调用一次原 `tasks.market()`**，不加新的重复 HTTP、历史查询或自动重试；原 HTTP 自己的既有行为不变。HTTP 成功按原流程继续；HTTP 失败按原流程失败，不能再返回过期本地结果兜底。只对可用性读取捕获异常，不能把账户撤销/取消或交易保护异常吞掉当成 HTTP fallback。
6. HTTP 回退一旦开始，晚到的本地响应不能覆盖结果；本地结果已选定后不另起竞争 HTTP。记录来源、原因、耗时、attempt/leg 及簿身份，冻结本次输入。异步期间的作废必须使尚未完成的本地结果失效；开关关闭不得触发重下单。已发送订单继续原成交确认/补单语义，**绝不能因本地故障或提交响应超时再用 HTTP 路径重下订单**。

| 事件/状态 | 对本次预检的要求 | 对本地服务/PM-M 的要求 |
| --- | --- | --- |
| 无快照、超出 16 资产准入、未订阅、过期、元数据未知、tick 模式未支持 | 立即原 HTTP；按原因计数，不临时等待热身 | 不扩订阅；恢复必须等合格证据 |
| 断线/换源/epoch 变化、坏帧、乱序/可检测缺帧、对账差异、tick 变化 | 放弃当前本地读取，原 HTTP；不得使用旧代次结果 | 按失效范围作废本地簿；不控制 PM-M 重连；差异触发停用快路径并审计 |
| Worker 异常、队列/CPU 超限、ACK/读超时、后台恢复后旧数据 | 原 HTTP，迟到返回丢弃 | 失效服务不自动复活；不可为覆盖率放宽资源/年龄限制 |
| 登录退出/凭据撤销/尝试取消 | 沿用取消和保护，不尝试靠 HTTP 绕过 | 停止授权作用域；旧回调无效 |

本地 FIFO 序号/ACK 仅证明本地处理顺序，不是交易所连续序号；毫秒时间戳也不是序号。不能宣称所有上游静默遗漏都可检测或与官方每一瞬间完全相同。必须保留失效保护、周期独立对账和 HTTP 兜底；无法证明安全衔接的恢复阶段继续 HTTP。回退 HTTP 也不能保证随后撮合一定成交。

## 2. 范围与不可变约束

### 2.1 快路径适用条件

同时满足以下条件才允许读 WS 证据；不满足只代表走原路径，不是拒单理由：

1. 本轮 `capturePmFokPreflightMode(option)` 为 `optimized`，且为 FOK。
2. 官方行情源 `getPmMarketWsSourceMode() === "official"`。
3. HTTP 读取 `resolvePmHttpMode() === "direct"`。
4. 提交 `resolvePmOrderSubmitHttpMode() === "direct"`。
5. 本轮 gateway 规范化后与订阅的官方 CLOB 来源一致；资产、condition 对应关系已验证。
6. 新功能处于明确的启用阶段，专属 runtime 已就绪；V1 未携带 tick 报价。
7. 当前缓存、元数据、连接代次和新鲜度符合第 5 节。

## 5. 状态与证据模型

每个资产记录：官方 origin、tokenId、conditionId、runtime generation、connection epoch、subscription generation、book revision、完整 bids/asks、最后完整快照时间、最后已应用事件时间、本地接收/处理时间、元数据版本、可信状态及原因。

`revision` 只代表本地处理顺序，不能证明官方无漏帧。`sourceTimestamp` 与本地接收时间分开，不直接用未经校时的跨时钟差判断延迟；过期计算使用单调时钟，同时保留现有报价比较需要的接收墙钟时间。

状态：`WAIT_SNAPSHOT` → `READY`；断线、暂停、异常进入 `UNTRUSTED`；新连接回到 `WAIT_SNAPSHOT`。元数据缺失、过期或资源限制也使读取返回 miss。`CONNECTED`、PONG、其他资产有更新均不能代替本资产就绪。

### 5.1 快照与增量

1. 对帧先完整验证，再提交更新；不能部分更新后才因另一个价位解析失败退出。
2. 同连接按接收顺序处理；不对 timestamp 重排序，不异步并行处理造成乱序。
3. 首个有效完整 `book` 原子建立全簿。此前增量丢弃，不事后覆盖该快照；若能观察到快照倒退/时序矛盾则继续不可信。
4. `price_change` 按 side 和规范化价格键覆盖新聚合 size，size=0 删除。缺失/非法数量不能当成零；相同 timestamp 不等于重复消息。
5. 后续有效完整 book 整体替换，不能合并旧价位；合法空簿不等同于解析失败。
6. `best_bid_ask` 仅作一致性线索，不补造深度；不同事件未对齐时不武断判错。`last_trade_price` 不再次扣减数量。
7. 时间倒退、资产错配、无法解释的矛盾、丢帧/积压等取消该簿可信状态，等待完整重建。
8. 只发布完整事务后的版本。预检拿不可变副本，不能将活动 Map/数组引用放入 `option.data`。
9. 后到完整 book 的 hash 可用于其快照身份；不把 `price_change.hash` 当完整簿 hash。增量后的状态不继续冒用旧快照 hash 声称已校验。

### 5.2 元数据与时间

- 提前通过官方 HTTP 取得 `version`、`neg_risk`、`min_order_size`、tick 和资产身份，沿用 `polymarketMarketOrderOptions` 的合法性规则。WS 缺字段不意味着合法默认值。
- HTTP 只提供元数据/本轮回退/对照；HTTP 深度不覆盖活动 WS 簿，不做“HTTP 返回后按时间重放增量”的未经证明拼接。
- 请求开始捕获 runtime/connection/subscription/metadata revision；响应回到旧代次或期间有更新时，不覆盖较新状态。重新请求在后台完成，本轮不等。
- 私有 tick/control 状态不写公共 `notePmTickFrame`、`notePmTickBufferBook` 或 `fo`。元数据与已知公共控制值矛盾时快路径 miss，由原 HTTP 处理。
- V1 的 tick 报价始终 HTTP，因此不会因 WS 成功进入共享 tick 回写分支；覆盖所有 tick 报价表达方式的测试是上线条件。
- 证据读取不刷新接收时间，心跳不刷新盘口证据时间。安静盘口可因保守有效期退回 HTTP，但不能标为市场锁盘。
- 上线前在影子阶段选择并冻结证据有效期、元数据 TTL、积压上限和复核周期，记录依据。可比较 250/500/1000ms 等本地证据窗口，这些仅为实验参数，不是官方安全承诺。
- 必须有完整快照复核/重建周期，不能仅因不断收到零星增量就无限续期。复核无法建立一致性则撤销快路径资格；不得为了命中率延长有效期掩盖问题。

## 6. HTTP 回退及错误边界

| 情况 | V1 行为 |
| --- | --- |
| 条件不适用、功能关闭或模块尚未加载 | 原 HTTP，不等加载 |
| 无快照、缺元数据、过期、断线、超限、异常 | 立即原 HTTP，不等恢复 |
| WS 计算足额、价格及元数据有效 | 返回快路径结果，进入原预检收尾 |
| WS 价格越界、深度不足、最小份数不足等负判断 | 记录负判断，原 HTTP 确认一次；不直接触发公共报价回写 |
| 快路径自身抛错 | 记录、隔离相关缓存，原 HTTP 一次 |
| 原 HTTP 失败或原钱包/参数/本地赛况检查失败 | 按原行为结束；不再反向读 WS 寻找通过结果 |

上述“一次”指调用现有 `pmGetBook` 预检流程一次，其内部现有传输回退保持不变，不承诺底层网络只发一个请求。新增后台预取不能被用作该回退的旧在途响应。

这是对原讨论“可信 WS 负判断直接失败”的收紧：先以肯定结果加速，避免新来源的错误拒绝和公共 `fo` 回写污染。它不是投注重试，不签单、不提交、不修改原限价。原 HTTP 结果仍可按既有语义更新 `fo`。

快路径 try/catch 仅包围缓存读取与纯盘口候选计算，不包围外层钱包、凭据、绑定、行情锁盘等错误；不能用“回退”吞掉这些原有保护。

预检冻结后不追加 WS 数量门控，不重签、不重价、不重拉簿。WS 随后断线只影响后续证据获取；首腿已成交时不因本功能新增拒单。现有提交入口及发送锁后的所有校验完整保留。

## 9. 性能与双腿成交验证

### 9.1 影子证据

记录 `linkId + attemptId + leg`、冻结模式、真实路由、阶段/实验分组、簿来源、连接代次、版本、时间、快路径耗时、回退原因、限价内可成交金额、原 HTTP 耗时及差异分类。元数据预取与冷启动耗时单列，不能从整条尝试里删掉后宣称加速。

当前部分 book/check/pair_check 指标没有完整关联字段。优先利用现有 observation/trace 的只读监听与动态专属上下文；若无法可靠关联，就把样本记为未关联，不能按 token 或时间邻近猜测，也不能为补指标改写双腿提交逻辑。

HTTP 对照不是同时刻真值。保存有界 WS 历史，区分能对齐的完整状态、请求期间正常变化和无法对齐；不把 HTTP 返回时的最新 WS 簿直接用于判错。重点统计错误通过、错误否定、深度差异、断线恢复、资源开销、快路径命中率及其分母。

P50/P95 同时记录 PM 预检、双腿预检、准备到实际发送的整条时长。现有 `bookAgeMs` 不是完整的发送时行情年龄，动态旁路应分别保存源事件、接收、选用、真正发送时间，不改变旧指标定义。另一腿较慢时，PM 预检变快不一定缩短双腿等待。

### 9.2 实际 A/B

- 对照：当前 optimized + HTTP；实验：optimized + WS 肯定快路径/HTTP 回退。经典用户不随机分组、不切换设置。
- 分组发生在是否命中 WS、是否通过预检之前；每个机会只能向场馆提交一组真实订单，不同时交易两组作比较。
- 同条件分层：对手场馆、顺序/并行、赛前/滚球、注码、深度、利润区间、市场延迟、账号及直连线路；同市场/时间区间聚类，考虑重复机会和相互消耗流动性的影响。
- 分母包括分组后的全部合格尝试（含快路径未命中、回退和失败）；不能只报告命中成功样本。
- 主指标：初始双腿均成交比例；首腿已成功而 PM 未成交的比例/金额；每小时完成组数。补单后完成单独统计。
- 同时评估净收益、补单成本、未决订单与单腿敞口。受理/delayed 不计作成交，MATCHED 与最终确认沿用现有业务口径并分别保留。
- 试验前确定最小有意义提升、允许的敞口/收益非劣界限和样本量，以置信区间报告结果；未决单不删样本。一次小样本改善不作为上线依据。
- 若只是减少预检时间而双腿收益无显著改善，结论必须写为“延迟改善，成交收益尚未证明”，不能宣称成交率已提升。

PM 的市场撮合延迟、竞争撤单和其他交易者消费深度均不可由本地快路径消除；不承诺完整本地簿能够预留流动性。

- 每资产保留最近 4 个不可变完整状态，主线程保留最近 256 条 HTTP attempt 和最多 32 条 probe 摘要、32 个比较上下文。比较上下文 10 秒过期，容量超限和过期的 HTTP 完成仍进入总计数及最近样本；样本淘汰不减少总计数。历史不够时标记无法对齐，不能猜测状态或认定错误通过。
- 缺失初始快照超过 8 秒只隔离对应 token，不清空健康资产；每代通知一次，等待迟到完整快照或下一次 60 秒周期。Worker 加载/运行失败直接停旁路，不在主线程接管深度。
- 独立 HTTP probe 最快每 3 秒一个，全局并发 1，超时 5 秒，响应上限 1MB；轮询候选，专属 metadata TTL 为 60 秒。HTTP 不写 WS 簿，不写共享 tick/fo。
- 本地簿 1,000ms、源时间 5,000ms、未来偏移容差 1,000ms 仅是影子 miss 分类参数；尚未验证为交易安全阈值。60 秒重新建立完整快照；断线、坏帧、超限、tick 变化、可对齐差异都会废弃独立代次。
- HTTP metadata 复用当前纯校验器的版本规则：HTTP `version: "v2"` 对应签名版本 3，经过完整约束校验的旧 HTTP schema 对应版本 2；未知版本不可用。**不能从 WS 缺少 version 推断版本。**
- 报告保留已有 `linkId`、`attemptId`、`executionId` 和 token/方向构成的 leg key；缺失就保持未关联，不推测 A/B 腿。`precheckOnly` 时长单列，不混入执行腿统计。
- `httpMarketMs` 是主线程记录的现有 HTTP market 等待；`beginQueueMs`、`observerQueueMs`、`compareMs` 独立记录两次消息排队与 Worker 比较。`localReadMs` 只测 Worker 内本地取证成本，且读簿可能晚于主线程发起时刻，未执行完整可下单价格算法。`depthAtHttpFillPrice` 仅表示本轮 HTTP 填单价以内的影子深度，不冒充冻结检测上限的精确决策结果。

## 13. 五项修复后的实施与生产旁路结论

订单簿核心独立，动态复核是消费者。五项修复分别覆盖每帧复制和 Worker 隔离、同候选恢复、缺失资产隔离、运行时不可变视图、所有准入 HTTP 完成的统计分母。完整说明、最终回归与浏览器证据见 [重新审计报告](./audits/PM_WS_BOOK_SHADOW_REAUDIT_20261016.md)。

允许少量满足全部直连条件的动态用户按照 12.2 显式开启旁路。默认保持关闭；经典用户无需变更任何配置。上线先确认 Worker 正常、确有快照/probe、`executionSource` 为 `existing-http` 且 `activeSupported` 为 false。Worker 不可用、持续超时/差异或出现用户侧卡顿时关闭旁路并导出报告。

这一结论只放行公开行情维护和诊断取证，不证明真实预检提速或双腿成交率提升，不授权 active，也不授权替经典预检切换数据源。
