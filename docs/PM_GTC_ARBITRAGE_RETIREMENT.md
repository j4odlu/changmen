# GTC 退出自动套利

[changmen 扩展] 2026-10-27。用户明确：当前 GTC 不参与套利，PM GTC 单笔下单能力保留，供以后其它业务使用。本轮只修改客户端，不迁移数据库或删除历史订单。

[changmen 扩展] 后续单笔模块化见 [PM 单笔 GTC 订单模块](./PM_GTC_ORDER_MODULE.md)：新 GTC 已直接使用单笔存储、监控及公共订单结果，不再转换为旧双腿计划；旧格式只处理历史记录。此后续改动涉及共享模块，发布验证范围覆盖前后端。

## 新套利

- PM 自动套利仅使用现有 FOK 预检、提交、确认、选号、计次及收尾。LOS、9999 与其它场馆组合保留各自业务规则。
- 删除 GTC 自动套利创建桥 `orderModes/gtc/arbLeg.ts`、专属选号恢复 `selectionHistory.ts` 及公共阶段的 `originalExecution` 接线。套利不读取 GTC 成交历史、不等待 GTC 恢复，不接收 GTC 动作许可。
- 按用户补充确认“当前无人使用 GTC 套利”，整块“PM 自动套利下单模式”设置及启用确认已删除，不增加迁移确认或暂停流程。自动套利固定走原 FOK 链路，原有自动下注开关、经典/动态预检设置照常生效。
- 退役 `pmArbOrderMode`、`pmGtcV1Activation` 的类型、默认值和归一化字段；读取旧配置时忽略，下次保存时不再写入。保留手动/历史 GTC 的参与标记与订单恢复资料。

## 保留能力与兼容

- PM adapter 的 GTC 预检、签单、一次提交、精确原单查询、成交归并和撤单能力保留；现有显式手动 GTC 入口继续使用这些能力。
- `gtcOrderMonitor`、`gtcOrderSync`、本地 IndexedDB 记录、已消费发送许可及服务端财务接口保持。已有 GTC 原单和历史双腿执行继续恢复、监控、撤余量、关联对侧、核对费用及同步财务结果，恢复不重发原始买单或对侧。
- 旧 `GtcPlan` 中的双腿字段与 `other`、`groupComplete` 等状态仅供历史执行兼容使用，不应作为未来业务的新套利执行契约。未来业务应组合 PM 单笔订单能力与自身业务状态。
- 不合并原 FOK 与旧 GTC 计次历史，不重写金额、费用、余仓、盈亏及历史订单身份。旧单的 GTC 标识仍用于保护原单和避免被自动卖出扫描接管。

## 验证

自动套利的模式路由与历史测试验证旧模式配置不再参与执行、原公共历史仍生效；配置与界面回归验证旧模式字段被忽略和移除、模式选择及迁移面板均不再展示。架构测试禁止自动套利重新依赖 GTC 创建或历史模块。

保留并运行手动 GTC、原单监控、恢复、同步、成交修订、展示及人工卖出相关测试。所有验证使用离线模拟，不发送真实买入、卖出或撤单。

此前统一 GTC 套利与专项源码保护文档均为当时实现的历史记录。当前日常验证使用 `npm run check:change`；历史 FOK/GTC 源码快照未重设，不能将旧专项审计结果作为本次验收。
