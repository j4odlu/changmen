# GTC 监控隔离检查（2026-10-14）

[changmen 扩展] GTC 登录生命周期、PM HTTP/WS 核对、撤单、服务端记录恢复及对侧事实消费统一由 `client/web/src/runtime/gtcOrderMonitor/` 持有。App 单独挂载此模块；旧监控和执行入口仅兼容再导出，避免增加另一组定时器。

恢复仍是载入既有执行和财务记录，不发送首单、不重发第二腿。RAY 原监控及查询快照由 `rayOrderMonitor` 独立持有，GTC 启停不清空其状态。首次发送、公共账号 gateway、FOK 规则、数据库和日常部署策略不在本次提交范围。

## 发现并修复

- RAY 最终财务记录在首次本地核对/计次失败后曾被提前登记为已消费，同一记录不再重试。修复后失败清除消费标记，使用现有恢复退避规则进行本地核对，避免即时循环；停止监控会清理重试状态。
- PM 请求只核对原账号对象，账号对象被新凭证替换时未拒绝旧响应；应用事实或计次的异步返回后也缺少再次校验。修复后重新读取当前账号并核对会话，阻止旧请求继续更新及计次；撤单发送和响应也核对同一绑定。
- adapter 深路径导入检查仍登记旧监控目录，迁移后会阻断 CI。将两处授权路径迁到新目录，保持原单点限制。

## 验证范围

新增回归复现覆盖 RAY 核对失败后的恢复、重复失败退避和停止，以及 PM 会话中途结束、账号凭证被替换。另验证监控重复启动、兼容入口共用实例、RAY/GTC 独立启停、原单恢复失败不阻断官方核对、终态停止、已保存成交恢复及原单不重发。

使用干净候选工作目录运行前端完整测试、包含 vue-tsc 的生产构建、客户端/服务端边界检查及固定 551 项 FOK 源码保护；不重置保护基线、不运行公网资源专项捕获。

验证结果：前端 3844 项通过、1 项跳过；后端测试任务 11/11 成功；验证脚本 1560 项通过，发布校验控制 51 项通过；551 项固定源码保护、router 编译及生产构建均通过。
