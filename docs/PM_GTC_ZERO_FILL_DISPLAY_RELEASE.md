## 问题与结果

[changmen 扩展] 生产只读核对发现 5 条已受理、零成交且没有对应财务行的 GTC 原单。登录页面确认这 5 条已经渲染，但全部位于普通订单列表之后，第一条距页面顶部约 1.1 万像素。它们均未释放，不能把当前漏显仅归因于释放记录被过滤，也不是 orders 并表导致。

零成交区改为放在日期筛选之后、普通财务订单之前，沿用现有订单卡片及 Link 排序。另补上零成交列表的独立只读加载，使显示不依赖执行器是否启动；已释放的零成交原单按 Link 日期保留。非零成交待入库卡片继续使用原来的位置和规则。

## 发布边界

仅修改前端显示代码、对应回归和本文档。生产代码为 OrderView 插槽、OrderHost、PendingOrders、ProgressPanel 的只读控制、orderDisplayProjection 和新增 displayRecords。

- `Pm_GtcList` 只读加载，15 秒轮询，同一代请求不重入；换用户、退出、销毁和过期会话响应丢弃。
- 不调用创建、执行命令、撤单或执行器启动；不更新 `gtcProgress`、财务 OrderStore 或用户偏好。
- 只读记录不能启用撤单按钮；执行器已有同用户、同 ID 且不旧于显示版本的记录时，沿用已有撤单资格。
- 财务列表、统计、删除、首次入库通知及其数据源不变。显示行复用卡片，不插入 orders。
- 下注、FOK、拒单检测、补单、恢复、共享状态机、场馆代码、后端及部署脚本均无修改。
- 不带入 orders 并表代码，不执行数据库迁移、回填或其他数据库写操作。`pm_gtc_executions` 保持当前执行控制的数据源。
- 管理端嵌入工作区不加载或显示当前用户的 GTC 记录。
