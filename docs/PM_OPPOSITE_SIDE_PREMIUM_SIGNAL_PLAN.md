# PM 高赔领先与反向低赔溢价观察执行方案

[changmen 扩展] 日期：2026-10-19。版本：1.1。状态：已按[首轮审计](./PM_OPPOSITE_SIDE_PREMIUM_SIGNAL_AUDIT_20261019.md)修订设计，业务功能尚未实施；修订对应关系见第 13 节，运行效果仍须按阶段验收。

目标是在同一场比赛、同一张地图的双边获胜盘口中，先判断 PM 高赔率一侧是否在所选场馆中最高，再观察其他场馆对 PM 低赔率一侧给出的赔率溢价。先完成独立监控和样本验证，再根据验证结果决定是否接入单边下注。

本次交付范围为执行方案文档。以下文件布局、参数、阶段和验收门槛均为后续实施设计，不表示相应功能已经存在，也不授权部署或真实下注。

## 1 策略定义与首期范围

用户原始思路：同一地图主客两侧有高赔和低赔；当 PM 的高赔是各馆最高时，观察其他场馆在相反低赔侧比 PM 多给多少赔率。

首期对象为电竞指定地图获胜盘口，要求地图编号大于 0、只有主客两个互斥且覆盖全部有效胜负结果的选项。全场、让分、大小、附加玩法和三项盘口不自动纳入；走盘、取消、弃权、重赛等结算规则不一致的市场不能混算。

观察方向由 PM 当时的两侧赔率决定，不固定主队或客队。比较必须对应同一支队伍，不能将各场馆各自的高赔直接放在一起比较。

首期比较集合建议明确选择 OB、RAY、PB，后续按数据质量扩展现有 registry 支持的场馆。界面使用“所选 3 馆中最高”等表述，不宣称覆盖所有外部场馆。场馆集合写入每条样本，不能在缺数据时悄悄缩小集合。

首期提供观察列表、参数设置、触发快照、信号生命周期、样本导出和结果评估。信号不进入现有套利选腿、正 EV 自动下注或订单队列；PM 在本策略中首先是参考场馆，候选下注方向是其他场馆上的 PM 低赔队伍。

## 2 计算口径

### 2.1 原始赔率和方向

设 PM 原始主客卖一价格为 `aHome`、`aAway`，均为大于 0、小于 1 的有效概率价格：

```text
PM 主队原始十进制赔率 = 1 / aHome
PM 客队原始十进制赔率 = 1 / aAway
H = PM 两侧中较高的赔率
L = PM 两侧中较低的赔率
highSide = H 对应的队伍方向
lowSide  = L 对应的相反方向
```

PM 两侧近似相等时标为方向不明确，不生成定向信号。默认只用浮点容差判断相等，不人为固定强弱队；后续若增加接近均势排除带，应作为独立参数和实验分组。

PM 可从 `oddsStore.getPmQuoteEntry` 获取原始条目并读取有效 `clobPrice`，但缓存只证明当前保存的数值；严格研究资格另外依赖第 3 节规定的来源和接收证据。原始卖一缺失时显示“缺少原始报价”，首期不通过三位展示赔率取倒数重建，也不把读取缓存的时间变成行情接收时间。

PM 的百分比缓冲、加一 tick、UI 截断和冻结订单价均不参与信号计算。传统场馆读取现有标准化十进制赔率；实现时核对各场馆 odds 原值的含义，在信号快照中同时保留计算值和界面展示值，比较前不额外舍入。

### 2.2 PM 高赔领先条件

对每个参与场馆 `v`，读取它在 `highSide` 的赔率 `O(v, highSide)`：

```text
M = max(O(v, highSide))
高赔领先率 leadPct = (H / M - 1) × 100%
独占最高 = H > M，差异超过浮点容差
并列最高 = H 与 M 在容差内相等
```

默认使用独占最高；界面允许单独选择“包含并列”，并保存 `rankMode`。并列最高与独占最高的统计分开输出。`minLeadPct` 可设为 0 或更高，不能把显示舍入后的相等当作精确并列。首轮计算容差固定为 `abs(x-y) <= 1e-9 × max(1, abs(x), abs(y))`；方向比较、排名和精确并列选馆均用同一函数，容差变更升级 strategyVersion。

所选场馆均须在高赔比较侧有合格报价，且至少有两个非 PM 场馆可比较。所选某馆缺失、封盘或过期时，严格模式不成立；可以显示已知范围的比较结果，但标为“覆盖不足”，不混入合格信号。

目标场馆还须在 `lowSide` 有合格报价。其他场馆缺少低赔侧不影响高赔侧排名，但不能作为该侧目标，也不能用于完整双边概率诊断。

### 2.3 反向低赔溢价

```text
目标场馆低赔赔率 T = O(v, lowSide)
赔率差 deltaOdds = T - L
赔率溢价 premiumPct = (T / L - 1) × 100%
```

每个目标场馆分别输出，不能只保存当时最优场馆。保留最大溢价用于列表排序，同时保留全部目标，避免只看极值产生偏差。

示例为假设报价，不代表实时市场：

| 场馆 | 主队 | 客队 | 客队比 PM 高出的赔率 | 客队溢价 |
| --- | ---: | ---: | ---: | ---: |
| PM | 3.00 | 1.45 | 基准 | 基准 |
| OB | 2.70 | 1.50 | 0.05 | 3.45% |
| RAY | 2.80 | 1.52 | 0.07 | 4.83% |
| PB | 2.90 | 1.48 | 0.03 | 2.07% |

此时 PM 主队赔率独占最高，观察其他场馆客队赔率；RAY 客队的原始溢价最大。若 PM 客队变成高赔，整个判断对称翻转。

### 2.4 参考概率与预估收益

界面主指标命名为“赔率溢价”，不直接命名为 EV。可附带一组明确标注假设的参考计算：

```text
S = 1/H + 1/L
qLow = (1/L) / S
参考公平赔率 fairLow = 1 / qLow = 1 + L/H
相对 PM 归一化概率的预估收益率 = qLow × T - 1
```

上例 `S ≈ 1.02299`、`qLow ≈ 67.42%`、`fairLow ≈ 1.48333`。PB 的 1.48 虽比 PM 的 1.45 高出 2.07%，该参考预估收益率仍约为 -0.22%。这说明赔率溢价不能直接等同于预期利润。

PM 两侧卖一含买卖价差；上述归一化只是参考模型，不能证明 PM 概率更准确。保存 `S` 和两侧原始卖一；已有合法只读接口能提供 bid、深度和健康状态时再补充，缺失则标记未知，不为诊断新增订阅、HTTP 探针或 Worker 管理行为。

`S = 1` 可直接计算；`S < 1` 的数学归一化仍可计算，但标为双边报价异常或潜在套利待核，首期合格研究样本先单独隔离。不能直接复用现有 `removVig`，因为它会对 `S <= 1` 返回空值。

### 2.5 跨馆潜在套利与利润率诊断

对每个目标另存 `crossImplied = 1/H + 1/T`，按同一浮点容差分为小于 1、约等于 1、大于 1。小于 1 表示不含费用与成交约束的潜在双腿套利；它不改变原始单边观察定义，也不触发订单或改变经典 FOK 门控。

上例 PM 高赔 3.00 与 RAY 相反侧 1.52 的 `crossImplied ≈ 0.991228`，理论双腿毛回报率约为 0.885%。研究报告分别输出潜在套利区间和非套利区间的单边结果，避免把既有跨馆价差解释为排名条件独有的效果。

目标场馆双侧齐备时同时保存 `venueOverround = 1/O(v, highSide) + 1/T`、该馆归一化低赔概率以及与 PM qLow 的差。目标馆另一侧缺失时这些诊断为空，不能推断其利润率；PM bid、深度未知时同样保持未知。这些是解释和敏感性分析，不将归一化概率视为真实胜率。

本策略若只在其他场馆下注，实际收益只扣除目标场馆实际发生的费用、换汇及成交成本；不能把未执行的 PM 交易手续费扣到该单收益上。以后若另行研究 PM 对冲，须独立计算两腿成本并归类，不能混入单边结果。

## 3 数据有效性与时间口径

每个报价至少包含场馆、matchId、betId、平台赛事与盘口 ID、选项 ID、主客方向、标准化赔率、锁盘状态、来源和时间证据。PM 另含 token ID 和原始卖一。合场后的主客映射仍需抽样核对原始队伍，不能只凭名称相似判断一致。

### 3.1 来源能力和证据等级

当前缓存的 `time` 表示写入时间，`http/mqtt` 只表示粗粒度写入来源。PM 的 HTTP 种子和 HTTP book 纠偏都可能记为 http；已有路径可能保留旧 clobPrice 后重新写 time。业务回写同样可以刷新缓存时间。现有 PM quote 回调只保留 assetId、bestAsk，不能从该对象恢复上游 timestamp 或连接代次。

P0 必须先形成逐平台的字段能力表，列明入口、价格含义、来源类型、真实接收位置、源时间、请求耗时、状态、连接证据、更新顺序及缺失处理。新模块只能使用经核对的证据，不能仅凭“数据来自 oddsStore”升级为严格有效。

| 等级 | 能证明的内容 | 用途 |
| --- | --- | --- |
| Q0 缓存数值 | 只有缓存值/写入时间，或无法排除旧值复制、种子及业务回写 | 诊断展示，不进入主研究决策 |
| Q1 本地接收可证 | 在已核实的实际行情回调或 HTTP 响应入口捕获本侧报价，保留来源与观察时间；本模块未发生处理缺口 | 可进入本地接收有效研究层，不宣称交易所实时性已验证 |
| Q2 源时间可核 | 满足 Q1，且有可解释的源时间和对应连接/来源证据 | 单列增强证据研究层，仍不宣称发现所有上游静默遗漏 |

`originKind` 区分 `ws-quote`、`http-market-response`、`http-index-seed`、`http-book-correction`、`business-write`、`cache-copy`、`unknown`；不能靠 http/mqtt 猜具体来源。主研究首期只接纳核实后的 ws-quote 与 http-market-response。种子、业务回写和复制为 Q0；book 纠偏即使有真实响应，也只进诊断，避免其他下注活动选择性触发查询而污染观察总体。

严格研究表示满足本方案的本地证据要求，不等于交易所状态绝对同步。Q1/Q2、事件/轮询来源和连接证据未知的占比均分层报告；研究 manifest 固定可接受的组合。未核实入口一律 Q0，不能为了凑齐 OB/RAY/PB 覆盖而提升等级。

### 3.2 时间与顺序字段

| 字段 | 含义与使用方式 |
| --- | --- |
| sourceAt | 上游行情时间，可空；统一单位并检查源时钟偏差 |
| cacheWrittenAt | 缓存写入时间，仅作诊断，不代表原始卖一接收时间 |
| quoteObservedAt | 核实后的行情回调或 HTTP 响应实际到达观察入口的墙钟时间 |
| quoteObservedMono | 同一会话内对应的单调时钟，用于年龄、持续时间和调度延迟 |
| requestStartedAt | HTTP 请求开始时间；无法解释的长耗时响应不能直接作为新鲜研究报价 |
| lastPriceChangedAt | 最后一次价格变动时间，仅用于变价分析 |
| evaluatedAt | 计算信号的时间，不刷新行情年龄 |
| connectionEpoch | 若现有来源提供则保留，用于区分重连前后证据 |
| localSequence | 模块按收到事件顺序分配的递增编号，不冒充交易所连续序号 |
| observationMode | event 或 poll，区分事件观察与轮询截面 |
| observedAt | 后续回访实际完成时间，不能假装准时回访 |

上文 quoteObservedAt 替代含义容易混淆的 receivedAt；若实现保留 receivedAt 名称，schema 必须声明它严格等价于 quoteObservedAt。只读取缓存的扫描不生成新的 quoteObservedAt。真正收到同价行情可以更新本地接收证据；心跳、渲染、缓存重建和业务回写不可以。

本模块用同一会话的单调时钟计算持续时间和真实延迟，墙钟用于导出与跨系统对齐；检测到墙钟跳变时标记异常。同一 episode 不能跨 session 或浏览器恢复缺口；不同会话的单调时钟不直接相减。源时间缺失不能补成本机时间，源时钟异常降级或失效。

只在模块内补充元数据，不修改共享缓存既有写入规则；如果现有入口无法提供 Q1，P0 必须确定独立只读事件元数据的最小增补范围及冻结边界，或者明确该平台首期仅能做诊断。不得把无法恢复的接收证据留给 P2 临时猜测。

### 3.3 地图身份与市场状态

P0 按游戏和平台建立版本化资格表，核实地图获胜玩法、双边含义及取消/弃权等结算规则，记录 `marketEligibilityVersion`。地图编号大于 0 不是唯一资格依据；`isLive !== true` 也不等于赛前，因为当前模型没有完整的地图结束状态。

规范研究身份采用经核实的平台赛事/市场身份与地图编号映射出的 `fixtureKey/mapKey`，保存规范队伍、平台 ID 集合和映射版本。client matchId/betId 是定位字段，不单独作为跨重组合场的永久身份。无法证明身份连续时结束旧观察，禁止把未知的新 ID 自动接到旧地图或重复计作一次新的入场机会；该区间只进诊断。

状态判定优先级为：身份或玩法未核实 → 仅诊断；明确结束/取消/未打图 → 结束；本侧明确锁盘或来源已知断线 → 不可用；盘口聚合状态与单侧状态冲突 → 待核；其余满足已核实规则才为可观察。不同平台的聚合 Locked 是否代表整个市场，按资格表解释，不一律覆盖真实单侧状态。

为每图保留赛前、进行中、暂时封盘、已结束、未打图和未知状态及证据时间。旧地图不能靠缓存仍有正数重新变成赛前；未来地图须有未开始的正向证据。不能在前端推断并回写赛事真相。

### 3.4 严格快照和研究入选

1. 盘口属于同一地图、相同玩法和结算口径，主客映射已对齐。
2. PM 两侧、全部高赔比较侧和当前目标低赔侧均至少 Q1、未锁盘，属于 manifest 允许的来源组合。
3. 以真实本地接收证据计算的年龄和跨度满足配置；HTTP 请求耗时与可用源时间通过 P0 固定的规则，不能以收到响应为由忽略明显陈旧证据。
4. 来源未处于已知失效、断线、旧代次或本模块丢事件状态；无连接级证据时明确标为未知并按固定研究层处理，不标成已验证健康。
5. 地图资格明确且未结束，身份版本可解释；重连、后台恢复和映射变化后重新建立观察区间。

严格快照是数据质量判定，不包含排名、溢价和盈利判断。进一步区分原始观察、研究入选和政策决策：`S < 1` 的快照即使质量合格也仅进入隔离研究层，不进入首期主策略及基础对照决策；`crossImplied < 1` 则保留决策资格并作预定分层。覆盖不足、过期、锁盘、未知和结算待定均保留计数，异常不能补成 0、无限大或正溢价。

## 4 观察参数与信号生命周期

以下数值是首轮采样候选值，P0 根据接收间隔和数据覆盖实测确定并版本化；不是已验证的盈利参数。有效性阈值的调整须记录原因，不能只为增加信号数量而放宽。

| 参数 | 首轮候选值 | 作用 |
| --- | --- | --- |
| enabled | false | 功能默认关闭 |
| comparisonVenues | OB、RAY、PB | 显式比较集合 |
| minComparisonVenues | 2 | 非 PM 比较场馆最低数量；不替代严格覆盖要求 |
| rankMode | 独占最高 | 并列单独实验 |
| minLeadPct | 0% | 先不叠加未验证的领先幅度要求 |
| minPremiumPct | 3% | 活跃列表阈值；原始研究样本继续保留低于阈值的数据 |
| minDurationMs | 1000 | 连续有效满足条件后进入活跃状态 |
| maxQuoteAgeMs | 10000 | 首轮本机接收年龄上限，后续按场馆质量评估 |
| maxReceiveSkewMs | 2000 | 同次计算所用报价接收时间最大跨度 |
| uiCoalesceMs | 250 | 仅合并 UI 重绘；不跳过检测状态转移 |
| followUpSeconds | 5、15、30、60 | 触发后的行情回访 |
| popupNotification | false | 首期在应用内显示，不外发消息 |

活跃列表阈值不等于研究数据入库阈值。`minLeadPct`、`minPremiumPct`、持续时间等参数均写入配置快照和版本号。

生命周期采用“未满足 → 候选 → 活跃 → 结束”。同一配置、fixtureKey/mapKey、方向和目标场馆构成观察键；一次连续有效观察区间构成一个 episode。保持满足时更新当前值和极值，不重复创建信号。事件来源表示本模块收到的各次有序观察中未失守；轮询来源只表示各次轮询均满足，不能声称证明两次扫描之间的市场状态。两者不混算持续时间统计。

检测输入保留 `localSequence`、价格、状态、锁盘和身份变更，按接收顺序异步处理；回调只入有界队列，不进行全量扫描。UI 可以合并，影响条件的中间事件不可以合并掉。对一个批次内的“满足 → 不满足 → 满足”，必须结束前段并重新计时；若不能保留全部中间事件，则保守记录中断，而不是读取最终缓存后续接原计时。

候选期间任何必需报价无效或条件不满足，连续计时立即归零。活跃期间发生阈值失守、高赔排名变化、封盘、过期、断线、换图或方向翻转时结束 episode，并记录原因。PM 高低侧翻转先结束旧方向，再重新计算新方向，不能把历史方向改成当前方向。

上述排名失守规则属于 A 主策略。第 8 节的 B 基础政策须独立维护持续观察状态，只检查共同的数据资格、方向和低赔溢价，不因高赔排名变化而重置；否则 B 实际上也引入了排名条件，不能作为基础对照。

配置或比较集合变化、合场映射变化也结束旧 episode。数据恢复后新建 episode；若做通知去重，只抑制提醒次数，不合并跨无效区间的持续时间。信号不设任意上限溢价来隐藏异常，高值保留并展示质量原因。

`candidateAt` 为首次观察满足，`confirmedAt` 为已处理队列证明观察持续时间达到阈值的时刻；`decisionAt` 不早于 confirmedAt，且必须等当前接收批次处理完成并复核最新有效状态后产生。收到时间用于还原观察顺序，决策时间使用实际完成计算的时间，不把积压期间的历史好价补成可用决策。比如 0ms 满足、900ms 失守、950ms 恢复，1000ms 时只累计恢复后的 50ms。

## 7 样本记录与导出

仅记录触发信号不足以证明筛选有效，还要保存同一观察范围中未满足高赔排名条件的可比样本。

### 7.1 记录内容与分辨率

首期采用浏览器 IndexedDB 作为有界研究缓冲，设置使用独立 localStorage key。正式分析输入为通过校验的归档集合，不能把浏览器自动保留期限当成长期归档。研究数据不是赛事、账号或订单的真相来源，不自动上传 RDS，不写采集真相表，不保存 Cookie、令牌、账号密码、签名器或钱包数据。

记录分为行情截面、episode 事件和回访结果。截面至少包含以下字段：

| 字段组 | 内容 |
| --- | --- |
| 版本与唯一性 | schemaVersion、strategyVersion、configHash、studyId、sessionId、localSequence、snapshotId、episodeId |
| 身份 | fixtureKey/mapKey、游戏、比赛、地图、规范主客队、各馆赛事/盘口/选项 ID、资格与映射版本 |
| 报价 | 各馆两侧计算赔率、PM 原始卖一、可用 bid 和深度，缺失字段显式为空 |
| 时间与来源 | sourceAt、cacheWrittenAt、quoteObservedAt/Mono、evaluatedAt、originKind、等级、观察模式、可用连接代次 |
| 条件 | highSide、lowSide、H、L、比较集合、排名、leadPct、目标、premiumPct、S、qLow、crossImplied、venueOverround |
| 质量 | 覆盖、年龄、跨度、锁盘、断线、未知、缺口原因、严格快照与研究资格分别记录 |
| 生命周期 | 候选/活跃/结束、首次时间、峰值、持续时间、终止原因 |
| 决策与评估 | policyId、candidateAt、confirmedAt、decisionAt、scheduledEntryAt、actualObservationAt、effectiveDelayMs、冻结目标、费用模型版本、结果状态 |
| 归档与缺口 | archiveId、批次/分块序号、校验摘要、覆盖区间、队列丢弃与采样暂停事件 |

背景对照截面以每地图每秒最多一组为起点，保存范围内全部场馆报价；影响检测的报价/状态事件、episode 转移、政策决策和实际定时入场快照另行记录，不能受 1Hz 截面上限截断。静默区间可压缩，但不得丢失可解释的顺序、覆盖缺口或决定连续条件的转移。

0.5/1/2 秒入场及后续回访由在线任务在实际执行时捕获不可变快照，记录计划和实到时间。只保留 1Hz 数据的记录不能事后插值为亚秒入场；缺少在线入场快照则该次为不可观察，不补取后来有利价格。不能只保存最大溢价、赢家或事后成功记录。

### 7.2 容量与暂停规则

初始上限为同时观察 100 地图、UI 200 条历史行、IndexedDB 50 万条或估算 200 MiB。研究采样高水位为 40 万条或 160 MiB，任一先到暂停新研究采样及新政策决策，结束本会话未入场的观察，保留余量用于结束事件、状态索引和结果补录。余量不是浏览器配额保证，实际 quota 错误时也立即暂停。尚未执行的模拟入场标记中断，不虚构成交；已入场的记录保留后续结果关联。

按 100 地图每秒一条、未压缩计算，50 万条约 83 分钟即触顶，事件记录还会加快增长。因此 14 天是跨归档批次的研究观察目标，不是浏览器缓冲的保留承诺。不能清理未经核验归档的研究记录来维持采样，也不能仅记一个丢失计数后继续把研究称为完整。

超过地图预算时按已固定的身份排序选取，记录入选和排除范围；不得按结果或当前最高溢价改变总体。浏览器关闭、后台节流、暂停、重启和多标签页缺口均记录。多标签页使用独立 sessionId，研究 manifest 指定唯一主采样会话；其他会话仅作诊断，不能在看到优劣价格后选择性拼接主样本。

### 7.3 归档与可重建性

导出 JSONL 保存完整嵌套快照，CSV 提供每个目标场馆的扁平行；同时导出配置、字段说明、版本、采样间隔、丢弃计数和覆盖统计。JSONL 与 CSV 对同一记录的数值、方向和时间必须一致。刷新页面后未正常结束的 episode 标记为中断，不拼接成持续满足。

每次归档包含 manifest、递增批次号、分块号、每块 SHA-256、记录数量、首尾 localSequence、时间覆盖、缺口及 schema/配置版本。用户主动导出分块文件后，须重新选择全部文件进行读回校验；浏览器下载完成提示、创建 Blob 或生成摘要都不等于已保存可靠副本。只有内容、数量、连续性和摘要全部吻合并写入归档回执，才标为 `archivedVerified`。

回收仅允许删除已验证归档的原始事件和背景截面；未结算决策、不可变入场快照、结算状态、研究集归属、配置和归档索引持续保留，直到本研究显式结束且相关数据也已归档。回收后低于 25 万条且 100 MiB 才允许手动恢复采样，恢复从新会话区间起算，不拼接连续计时。归档失败、取消、缺块或重读不一致均不删除，容量不足则继续暂停。

分析工具必须核对批次链、去重 snapshotId、核对总数并列出全部缺口；同 ID 同内容重复导入可幂等接受，同 ID 不同内容为冲突。未结算时已归档的决定由独立结果批次引用固定 decisionId 补充，不能覆盖旧快照。离线归档丢失时该研究批次不能作为完整验证材料，须明确报告缺失并按预定缺失规则处理。

如果后续需要全天候、多设备统一样本，再单独设计服务端采样：先确认各馆行情实际可用来源，经 `@changmen/db`、API 契约和 Cookie/CSRF 路径接入，不假设当前 VPS 已有全部浏览器场馆报价。

## 8 策略验证设计

### 8.1 同一机会池上的政策比较

验证两个问题：PM 高赔最高时，反向溢价是否更可能随后收敛；在可解释的成交假设下，这些候选是否有优于对照的实际结算收益。

研究 manifest 在采样前固定游戏、场馆、证据层、地图资格、观察时段和容量选择规则。地图首次进入已固定范围且身份明确时即建立一条机会记录；其后没有信号、未下注或出现缺口都保留。排名与溢价不得决定地图是否进入总体，也不能事后只保留有完整好结果的地图。

在同一机会池上分别运行两个完整政策，使用相同的数据资格、溢价阈值、观察持续时间、主要延迟和成本模型：

| 政策 | 决策条件 | 比较方式 |
| --- | --- | --- |
| A 主策略 | PM 高赔独占最高，低赔侧达到阈值并满足持续观察 | 评价完整规则 |
| B 基础政策 | 同样要求低赔侧溢价及持续观察，忽略 PM 高赔排名 | 评价增加排名规则后整个政策的变化 |

A/B 可在同图不同时间决策，须各自记录方向和目标；最终比较的是完整政策的收益与覆盖，不把差额直接称为排名条件的因果效应。同一图在每个政策下最多一次冻结决策，三种预定延迟共享同一 decisionId、方向和目标，每种延迟最多一次入场观察。未入场、条件撤销和不可观察均消耗对应尝试，不等待下一次好价重选。无信号图在该政策下为零下注，数据中断不等于零下注。

主要比较以 mapKey 对齐，记录两政策各自的下注数、零下注数、撤销数、不可观察数及二者重合度，并按 fixtureKey 聚类。不能把 A 与包含 A 的 B 截面当成两个独立组。

### 8.2 互斥的描述性分组

另用下列互斥截面组解释信号来源。这些截面的数量不能当成独立投注数量，比较和误差估计仍按比赛聚类。

| 组别 | 定义 |
| --- | --- |
| D1 | 数据与研究资格合格、独占最高、低赔溢价达到阈值 |
| D2 | 同样合格且达到溢价阈值，但不满足独占最高，另标并列或落后 |
| D3 | 同样合格、独占最高，但溢价未达阈值 |
| D4 | 其余研究合格截面 |
| X | 数据资格不合格、PM S<1 隔离层及其他未知，按原因另列 |

D1 与 D2 只在共同支持充分的游戏、时段、目标馆、PM 低赔区间、溢价区间及报价质量上作描述性比较。leadPct 是规则变量，不作为要求两组精确相同的匹配条件；正负区间决定组别时不存在那种共同支持。样本不重合或过少时报告无法比较，不扩大区间以追求显著性。

跨馆潜在套利/非套利、Q1/Q2、事件/轮询、赛前/滚盘均作预定子报告；未预登记的最佳子组只能作为后续研究假设。

### 8.3 决策冻结与在线入场

决策时序固定为 `candidateAt → confirmedAt → decisionAt → scheduledEntryAt → actualObservationAt`。decisionAt 是实际完成队列处理和条件复核的时间，scheduledEntryAt 等于该时间加预定延迟，不从首次候选回溯。主要延迟预定为 1 秒；0.5 秒和 2 秒只作敏感性分析，不能看完结果后择优替换主指标。

每政策在同图首次能决策时，仅在当时满足该政策持续条件的目标中按当前溢价取最高，容差内按固定 OB、RAY、PB 顺序选取；冻结 side、目标馆、mapKey、配置、全馆快照、决策报价和证据版本。不能用 episode 后续峰值选馆，也不能为延迟后的好价更换目标。

模拟政策采用“入场时仍满足才入场”：任务实际执行时读取当前已收到并处理完的合格快照，复核该政策条件、冻结方向和目标、身份及来源连续性。条件明确不满足则撤销；缺少证据、队列未追上、后台暂停或超过 2 秒调度容忍窗口则不可观察；通过才固定 T_entry 并记录模拟入场。排队期间收到但未处理的撤价不能被忽略。

effectiveDelayMs 记录实际单调时钟差。容忍窗口内晚到的快照归入其真实延迟区间，不声称精确在 0.5/1/2 秒成交；主报告同时披露延迟分布。1Hz 背景截面不能替代在线快照或推断缺失时刻的报价。该模型没有真实受理及限额证据，结果名称保持为“报价模拟收益”。

### 8.4 行情回访

对已冻结的决策方向在 decisionAt 后 5、15、30、60 秒回访；已模拟入场的记录另可输出相对入场时刻的同组回访，二者分别命名。任务记录实到时间、最新可用报价及质量，超过计划时刻 2 秒则该回访缺失；不得检索未来窗口内最有利报价补齐。

计算固定队伍的目标赔率变化、溢价变化和相对后续 PM 参考概率的价格优势，并分别记录 PM 自身变化。溢价减小不一律解释成目标馆追随 PM；地图提前结束、身份变更或封盘均按原因缺失，不回填后续地图。

### 8.5 结算与收益记账

地图结果绑定同一比赛和地图身份；优先使用可追溯结果源，记录来源、读取时间和目标场馆适用结算规则。没有稳定自动结果源时，允许独立结果文件人工核验后导入。取消、走盘、弃权、结算冲突和待定单独分类，不推断成输赢。

每笔模拟本金固定为 1 单位；无费用时赢为 `T_entry - 1`、输为 `-1`、退本为 0，按目标规则处理部分退回。P4 manifest 固定逐馆费用、换汇及额外执行成本模型与版本，未知不能默认为零。缺少可信成本范围时只能输出毛收益和敏感性，不能通过成本后放行标准。不同币种统一到固定研究单位，记录采用的汇率时点及口径。

政策 p 的净收益为 Y_p；数据完整且政策明确未入场时该图 Y_p=0、下注额=0。不可观察、结果待定和身份冲突为 unknown，不归零、不作为输赢，也不从原总体消失。主报告固定以下两个联合判定指标：

```text
ROI_A = sum(Y_A) / sum(A 政策实际模拟下注本金)
DeltaPerMap = mean(Y_A - Y_B)，使用同一预定机会池
```

主报告包括 unknown 的数量、发生时段与两政策分布，并对其使用 manifest 预定的成本和赔付上下界作不利敏感性分析。若合理界限无法事前确定，或不利场景下结论不稳，则证据不足；不得仅删除未知图后报告漂亮的 DeltaPerMap。模拟入场后待定和冲突结算必须处理完才做最终盈利判定。

盈亏平衡胜率按每条入场赔率及成本计算；若赢净利为 w、输净损绝对值为 l，该条为 `l/(w+l)`。混合赔率不能用未定义的单个平均赔率阈值替代逐笔损益。固定 1 单位本金下的实现净值按结算时间、相同时按 decisionId 排序；最大回撤按单位本金计，另报最大同时未结算本金和按决策时间排序的敏感性。它不是实际账号资金收益率，也不模拟无限资金可执行性。

### 8.6 样本划分与明确的结论门槛

同一 fixtureKey 的全部地图和两政策始终在同一集合。按首次纳入机会池的时间排序，先探索、再验证、最后保留，不能把较晚结束的比赛按结果便利移组。初步工作量为探索约 120 场、验证约 40 场，保留集至少 40 场且满足探索期估计的样本需求；总计至少 14 个自然日、200 场独立比赛、500 个合格 episode 只是收集目标，不是自动放行条件。

探索期记录全部尝试参数，选定一套主要配置和适用总体；验证期仅作预定的方向与稳健性检查。若验证后改策略，升版本并重新完成对应探索/验证，不能继续沿用旧验证结果。最终 holdoutManifest 在保留集开始前锁定代码与配置摘要、身份规则、归档版本及批次接纳规则、入场与成本模型、结果规则、缺失上下界、候选数量、样本规模及停止规则；未来归档文件按该规则追加清单，不能在看到收益后选择批次。保留集结果只用于一次预定最终评价，不中途按收益挑选结束日或扩样至显著。

联合指标以 fixtureKey 为重采样簇，整场携带其全部地图和两政策，进行 10,000 次有放回 bootstrap，固定随机种子 20261019；每次重新计算 ROI_A 的比率和 DeltaPerMap，使用双侧 95% 百分位区间。A 无入场导致分母为零的重采样必须计数，不能悄悄删掉；出现任一次零分母或无法形成有效区间时，本批次不足以按该方法放行。仿真检验该区间方法的适用性是分析脚本验收项，不能在看到保留集结果后更换区间算法。

首轮最小有意义优势预定为 `ROI_A > 1%`、`DeltaPerMap > 0.002 单位/机会图`，要求两个指标的 95% 区间下界分别超过门槛才作为进入 P5 设计的支持证据。数值是研究标准，不是盈利预测；如需改变，必须在保留集开始前固定并说明理由，之后改变须使用新保留集。主指标只使用 1 秒主要延迟；多个次要组合的最好结果不能替代联合门槛。

采样缺口或入场不可观察占比超过机会池 5% 时，先改善数据并启动新批次；不超过 5% 也仍须通过上述不利缺失分析。最终入场结算未解决数要求为 0；一旦发现身份错配、来源时间造新、未校验归档丢失或事后改组，本批次不能作为放行证据。两联合指标和预定的套利/非套利、场馆、游戏子报告必须同时披露；只在预先固定且证据支持的范围内形成结论，不推广到未覆盖场馆。

满足数据与联合门槛才记为支持；有证据表明达不到预定优势则记为不支持；区间过宽、缺失无法约束或成本不可信则为证据不足。研究计划若未达到预定样本量，可以继续按事先固定的规则补足，不能看完保留集收益再选择补多少场。

## 9 分阶段实施与交付

工作量按单人有效开发时间粗估，不含等待比赛样本、生产发布和额外场馆适配；各阶段顺序依赖前一阶段的验收结果。

| 阶段 | 工作内容 | 交付物 | 完成条件 | 粗估 |
| --- | --- | --- | --- | --- |
| P0 数据核对 | 逐来源和逐游戏核对 Q1 能力、状态、永久身份、结算与时间语义 | 字段能力表、资格表、脱敏快照、最小只读增补范围、配置版本 | 每个主研究来源至少 Q1；不能达到的明确仅诊断，不进入后续研究验收 | 1 至 2 天，额外接入另估 |
| P1 纯计算 | 定义计算、质量、隔离层和两政策输入输出 | calculator、types、固定反例测试 | 公式、方向、容差、S 与跨馆分类可离线复现 | 0.5 至 1 天 |
| P2 独立监控 | 有序检测、决策时钟、状态资格、设置与面板 | 独立模块、生命周期/积压测试、人工对照记录 | 不跳过中间失效，不从候选回溯决策，既有下注不受影响 | 1.5 至 3 天 |
| P3 研究记录 | 在线入场快照、对照采样、有界队列、归档读回、结果导入 | 可重建归档、策略回放、压力/配额/缺块测试 | 全部关键决定可重建，未归档不删除，亚秒结果不依赖 1Hz 插值 | 2 至 4 天 |
| P4 效果验证 | 预登记、探索/验证/保留集、成本与缺失分析、联合指标 | 锁定 manifest、分析脚本、覆盖与策略报告 | 达到第 8.6 节标准，或明确报告证据不足/不支持 | 至少 14 天观察，样本量按预定功效规则，另加分析时间 |
| P5 下注接入设计 | 仅在用户后续要求且 P4 有支持证据时制定单边执行方案 | 单边执行契约、资金与重复下注规则、独立验收方案 | 明确目标馆账号、限额、价格重验、确认与失败行为 | 另估 |

P0 首批建议核对不少于 20 个双边盘口快照，覆盖 PM 高赔在主侧/客侧、均势、锁盘和断线恢复；样本不足不能以构造数据代替真实来源核对。P2 连续运行至少 30 分钟并人工抽查 20 个候选或无效状态，记录零信号场景，不能只核对成功触发。

P0 的关键能力缺口不能通过“等 P2 再补标签”放行。P2 前固定有序输入、观察模式和决策时间契约；P3 前固定归档及资源契约；P4 前通过同一机会池的两政策回放与 bootstrap 仿真，并登记探索、验证和保留的具体边界。未满足某阶段前置条件时，只推进不依赖该缺口的工作。

首期先完成 P0 至 P3 的观察工具，再进入 P4 收集证据。P5 属于后续独立工作，不由本次文档自动启动；不提前接入自动下注、自动补单或资金放大。

### 10.3 有界队列与存储故障

以下为初始资源预算，P2/P3 压测后只能按完整记录的版本调整，不能以悄悄丢事件保住表面命中率：

| 环节 | 初始上限与处理 |
| --- | --- |
| 有序输入队列 | 4096 事件或估算 4 MiB，任一先到记录缺口并使受影响 episode 失效 |
| 单次检测任务 | 最多 256 事件且时间预算 4ms，处理后让出主线程；超预算不回溯生成历史决策 |
| 待写队列 | 4096 记录或 4 MiB，最多一个 IndexedDB 写事务在途，每批最多 256 条/256 KiB |
| 入场和回访 | 最多 2048 个待调度任务；单次最多处理 32 个，检查真实迟到和队列是否追上 |
| 导出与读回 | 每文件块最多 8 MiB，最多两个块在内存中，流式生成/核对；不得一次载入全部研究 |
| UI 刷新 | 250ms 合并一次，深度/历史表按需呈现，不在同步行情回调中序列化 |

首次容量或事务错误暂停研究入选和新决策，停止向待写队列追加无界数据；优先保存结束和 gap 事件。若此时连 gap 也无法落盘，下次启动根据未正常结束的 session 标为中断，不能假称有完整覆盖。已知受影响资产使其仍开放的观察区间失效，无法界定范围则该会话所有仍开放区间失效；已完整记录的历史决定不覆盖或删除，其后尚未执行的模拟入场标为中断。缺口恢复必须从新观察区间起算。

对 quota/权限/版本冲突不无限自动重试，保留缓冲并提示归档或修复；瞬时事务失败最多一次有界重试，失败则维持暂停。旧 schema 只能经显式迁移和数量/摘要核对后启用，失败不清库重建。关闭模块立即停止监听和模拟任务，最多 1 秒异步完成已接纳的末批写入，超时保留可恢复记录并标记中断，不阻塞路由或下注。用户取消导出不产生归档回执。

### 10.4 运行验收与停用

以实施设备和实际比赛数量测量新增开销，初始目标为最多 100 地图时增量计算单批 p95 不超过 5ms、模块额外内存不超过 50 MiB、连续 30 分钟无模块引发的长任务。记录设备、覆盖数量和采样负载；未达标先降低重绘和改进索引，不靠放宽行情有效性解决。

功能关闭后不注册行情监听、不创建监控或模拟任务；仅允许上述有界收尾写入，完成后不再记录行情。开启后不新增 PM 订阅和业务 HTTP，不调用订单网关、不读取账号凭证；持久化失败、异常报价和资源超限均只影响本模块。

先在本机使用观察开关验证。发现队伍错配、报价时间造新、历史快照被修改、无法解释的覆盖变化或既有 FOK 行为改变，停止该模块并保留诊断与研究版本；修复后重新执行相关验收。生产发布另按仓库既有流程进行。

## 11 实施前待核实事项

以下事项由 P0 实测解决并形成字段能力表与资格表，允许明确降级为 Q0 诊断，但不得进入主研究决策：

1. OB、RAY、PB 的原始行情接收位置、缓存/种子/业务回写的区分能力、HTTP 耗时、逐资产新鲜证据与事件/轮询模式。
2. PM 初值、WS、本地缓存重建和 book 纠偏的可识别性；Q1 入口不足时，最小只读元数据增补是否能在既有冻结与 FOK 约束下实现。
3. 逐游戏地图资格、状态优先级、取消/弃权结算规则及 fixtureKey/mapKey 稳定身份和结果来源。
4. 只使用已有只读接口时，PM bid、深度和连接健康可取得的字段范围；缺失字段保持未知。
5. 实际刷新频率下的年龄/跨度覆盖、后台缺口、归档吞吐、字节估算及队列高水位；不能通过放宽证据等级解决覆盖不足。
