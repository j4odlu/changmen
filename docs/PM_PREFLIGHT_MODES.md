# PM 公共预检与 FOK 两种方式

[changmen 扩展] 用户配置 → 扩展 → PM FOK 预检方式。`Extensions.pmFokPreflightMode` 可取 `legacy` 或 `optimized`。默认、缺失及非法值均为 `legacy`。保存成功后才更新运行时；打开配置界面进行未保存的编辑不切换实际预检。账号配置加载时恢复选择，退出登录恢复默认。

FOK 每个新投注尝试冻结一次方式。自动套利在候选阶段冻结，人工 FOK 在预检入口冻结，之后切换配置不改变该尝试。失败重试建立新尝试时使用届时配置。GTC 不读取这个选项，继续使用公共优化检查。两种 FOK 方式均不在预检或提交时初始化、解锁或等待初始化钱包。

| 项目 | 原有预检（默认） | 优化预检 |
| --- | --- | --- |
| 赛况代码基准 | 2026-10-16 只读核验线上前后端 `a233e20534395b31401828e754432407b109053d`（原有 FOK 核心与 `1632d690` 一致） | 本轮客户端 Gamma 优化 |
| Gamma 市场 | 每轮请求，无短缓存 | 在途去重、请求开始计龄的 2 秒短缓存 |
| Gamma 赛事 | 保留线上 `shouldRefreshPmSportForBet`：无快照，或快照超过 45 秒且已开赛/临近开赛等条件才补查 | 每轮读取共享短缓存，过期即请求，不因 WS 较新而跳过 |
| 候选预热 | 不触发 | 有界预热，与正式预检复用 |
| CLOB 接单状态 | 每轮请求，明确拒绝时拦截；未知状态沿用线上处理 | 每轮请求，自动套利遇到未知状态也拦截 |
| 盘口返回后本地赛况复核 | 沿用线上预检时序 | 所有并行阶段返回后再检查本地终局 |
| 价格、份数、深度 | 共用 FOK 规则 | 共用 FOK 规则 |

原有方式的 45 秒是是否补查 Gamma 赛事的条件，并非等待 45 秒执行预检。它仅作为用户要求保留的线上行为存在于 `submission/preflight/legacy/`，优化方式与 GTC 不使用该条件。优化新增的提交前赛况复核只作用于优化 FOK 和 GTC；原有 FOK 保持线上提交语义。FOK 提交读取私有准备状态中冻结的方式，不读取当前用户配置或外部传入的方式。

公共模块 `packages/venue-adapter/polymarket/submission/preflight/pmBuyPreflight.ts` 并行调度模式层提供的盘口检查、赛况检查、提交校时、钱包就绪读取，返回具名 settled 结果，保留 FOK/GTC 各自的错误优先级。钱包状态仍归 `pmOrderClientCache` 管理，公共预检只读现成 runtime。9999 仅检查腿仍跳过签名钱包和校时，不能作为可提交的准备结果。

`fok/preflight.ts` 持有 FOK 准备状态、价格写回、最小份数和即时深度规则；`gtc/preparation.ts` 保留 GTC 的冻结限价和准备状态，自动套利要求限价内足额深度，人工挂单仍允许零即时深度。消费、签单、发送、成交确认和恢复仍在各模式执行器中。

旧赛况两个模块只调整 import 路径，并用测试逐字对照线上提交。新源码由 `pm-unified-preflight-boundary.mjs` 完整依赖哈希和精确增量保护；还原后仍通过原 FOK/VPS 基线，未替换任何原始基线。

本次发布不修改共用的服务端赛况输入：`polymarket-sports` 采集、`pm_sport` 写库、快照类型及相关依赖均保持线上 `a233e205`。WS 接管后拒绝 Gamma 覆盖、`updatedAt` 使用处理时间的语义保持不变；不引入 `receivedAt`。否则，即使原有预检判断代码不变，也会改变是否拦截及是否补查 Gamma。前端优化方式和 GTC 仍使用独立的短缓存、预热与每轮 CLOB 检查。

`scripts/verification/pm-legacy-input-parity.test.mjs` 固定核验这条输入链路，并对照线上真实状态写入代码回放 WS 接管后 Gamma 终局、WS 排队延迟两种场景；同时对照线上提取的并行任务，检查钱包已就绪时执行腿/仅检查腿的启动顺序和各类失败结果。与原有算法对照、FOK/GTC 模式切换和钱包生命周期测试共同构成验收，不以函数文本相同代替完整行为验证。
