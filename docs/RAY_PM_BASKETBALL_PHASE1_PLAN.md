## 运行时代码范围

RAY `collect.ts` 与 `shared/save_bets.ts` 恢复为本次修改前的代码，没有篮球专用分支、额外列表请求或独立采集器。原 `a8Collect` 自动读取游戏目录，原盘口解析器直接消费新增盘口 ID。

PM 没有修改 parser、discovery、行情索引、Sports 状态或下注的运行时实现；现有模块共同读取新增配置。篮球继续使用原全场获胜解析，单节、让分和大小分不新增支持。

共享目录增加通用 `clientGameId` 元数据支持，以便新增类别下发为 `10001`；同时修正缺失平台 ID 被转成字符串 `undefined` 后错误匹配的问题。原游戏仍使用原 `a8GameId`。

保留用户此前明确要求的两项篮球能力：

- 用户页与 matcher 显示篮球图标。
- 篮球允许只有一个场馆映射也生成 changmen 比赛并下发；仅此类别放宽场馆数量，原五款电竞的新比赛仍要求至少两馆。未关联规范队伍的单馆篮球沿用来源主客方向输出完整全场盘口，不伪造 changmen 队伍 ID。

单馆例外属于此前单独授权的 matcher 变更，不属于“新增游戏配置”本身。后续 PM 补入同场时沿用原队伍匹配、主客对齐和比赛 ID 复用规则。没有新增停止下注开关、停止合场规则、球队自动建档、名称模糊匹配或资金/订单改动。

## 沿用原逻辑的边界

RAY 各游戏使用同一混合列表接口，后续页也有其他电竞。保留原第一页采集意味着：篮球在后续页时本轮不会采到；这与原电竞的采集范围一致。此前增加的分页可能在失败时阻止原电竞列表刷新，当前已撤回整个分页实现。

RAY 继续使用源站 `team_name`、原 BO 和时间解析，不专门切换英文队名。PM 与 RAY 的不同名称仍需按原流程关联 changmen 队伍 ID，配置本身不能代替球队映射；未关联时可按已授权的篮球单馆例外分别下发。

RAY 真实篮球和 NBA2K 共享游戏 ID。本次不引入额外联赛过滤，保留源站球队身份，沿用原匹配逻辑；同队名基名但带 NBA2K 标记的不同来源不得误合。配置不宣称两馆覆盖所有相同联赛。

盘口锁盘、缺失字段、名称回退、状态转换、实时推送、可下注资格和订单执行均沿用原实现。没有新增篮球专用的完整性门控。真实下注验收及篮球比分/节次专用展示不在本次范围内。
