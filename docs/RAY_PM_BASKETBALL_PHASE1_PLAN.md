## 运行时代码范围

RAY `collect.ts` 仅将 `Home`、`Away` 和 `Teams[].Name` 的四处队名取值从 `team_name` 直接替换为 `team_short_name`，不回退中文；其余采集流程及 `shared/save_bets.ts` 保持原实现。没有篮球专用分支、额外列表请求或独立采集器。原 `a8Collect` 自动读取游戏目录，原盘口解析器直接消费新增盘口 ID。

PM 没有修改 parser、discovery、行情索引、Sports 状态或下注的运行时实现；现有模块共同读取新增配置。篮球继续使用原全场获胜解析，单节、让分和大小分不新增支持。

共享目录增加通用 `clientGameId` 元数据支持，以便新增类别下发为 `10001`；同时修正缺失平台 ID 被转成字符串 `undefined` 后错误匹配的问题。原游戏仍使用原 `a8GameId`。

用户页与 matcher 保留篮球图标。用户随后要求撤销篮球单馆下发：新篮球比赛恢复原至少两馆的合场门槛，撤回篮球专用单馆创建、方向投影及场馆数量例外，相关 matcher 运行文件恢复为接入前实现。

篮球是否成场由 matcher 原合场流程决定，用户接口不增加篮球过滤。撤回此前的读取出口过滤后，backend 恢复原字段投影和排序；不在读取时重新判断场馆数量。matcher 生成并保存合场结果，matcher 左栏展示和管理这些记录，用户端消费合场结果。

按用户要求，2026-10-25 独立清理单馆例外曾生成的 7 条历史合场记录 `8746–8752`，不伪造为已结束。维护入口 `rds/maintenance/remove-single-venue-basketball.mjs` 默认只读，写入前核对篮球类别、固定来源映射和订单引用并备份；仅删除这七个 ID 的合场行，由外键解除挂载，PM 来源及盘口保留。它们回到待匹配来源，后续按原规则形成新的合场记录。其他电竞原有比赛保留规则不变。没有新增停止下注开关、停止合场规则、球队自动建档、名称模糊匹配或资金/订单改动。

## 沿用原逻辑的边界

RAY 各游戏使用同一混合列表接口，后续页也有其他电竞。保留原第一页采集意味着：篮球在后续页时本轮不会采到；这与原电竞的采集范围一致。此前增加的分页可能在失败时阻止原电竞列表刷新，当前已撤回整个分页实现。

RAY 所有已配置游戏统一使用源站 `team_short_name`，原 BO 和时间解析不变。与 PM 英文名一致时可进入原名称匹配流程；不同全称、简称仍需按原流程关联 changmen 队伍 ID，字段切换本身不代替球队映射。未合为至少两馆时，篮球不下发用户，来源仍可在 matcher 查看和关联。

RAY 真实篮球和 NBA2K 共享游戏 ID。本次不引入额外联赛过滤，保留源站球队身份，沿用原匹配逻辑；同队名基名但带 NBA2K 标记的不同来源不得误合。配置不宣称两馆覆盖所有相同联赛。

盘口锁盘、缺失字段、名称回退、状态转换、实时推送、可下注资格和订单执行均沿用原实现。没有新增篮球专用的完整性门控。真实下注验收及篮球比分/节次专用展示不在本次范围内。
