# LOS 与 9999 前端仓位策略

[changmen 扩展] 2026-10-27。纯前端的独立模块，首版收集已有订单，具体交易策略后续接入。

## 入口与数据流

实现集中在 [singleLegStrategy.ts](../client/web/src/runtime/singleLegStrategy.ts)，由 App 初始化：

```text
现有 orderStore.orders 变化 → 筛选 LOS 和 9999 → 更新本会话仓位集合 → 策略回调
```

脚本使用 Vue 响应式监听，不新建轮询、HTTP 接口、数据库查询或后台进程。它读取完整缓存，不受侧栏账号筛选影响。订单加载及状态更新沿用现有前端链路，不调用套利扫描、预检、选号、补单和收尾。

## 当前行为

按 client-core 已有 Link 规则识别 LOS 和 9999，排除正 EV、普通套利、手动单、PM/PF 卖单及只读预览行。复制订单事实，避免策略直接修改原订单缓存。

`singleLegPositions` 是当前目标订单的只读快照列表，保留原有订单字段。首版不另设仓位状态机，不生成止盈止损判断，也不发送买卖或撤单。

监控列表随当前订单缓存更新，不额外保留历史仓位、恢复记录或去重状态。切换订单日期时跟随新的缓存；账号筛选不改变完整缓存。退出登录、切换用户、进入管理员预览或销毁应用作用域时清空；换用户或离开预览后等待现有加载流程交付新缓存。

范围是当前用户会话中已由前端加载到的订单；当前缓存未加载的历史订单不主动补拉。订单状态的更新频率沿用现有加载流程。刷新页面后重新收集，关闭页面后停止运行。

交易页面右下方的 `9999 / LOS` 按钮显示待处理数量，位置在降赔率按钮上方。按钮随 HomeView 挂载和卸载，进入管理后台后隐藏。展开后查看赛事、盘口、方向、账号、金额和状态；已平仓、已结算、拒单和退款订单不列入，待确认订单仍显示。该入口仅查看，不发起交易。

## 后续策略接口

`setupSingleLegStrategy(onPositions)` 默认调用同文件中的 `runSingleLegStrategy()`，目前为空函数。后续在这个独立函数中加入具体策略。

当前订单缓存变化后重新筛选，并在现有同步更新结束后调用策略。快照或策略回调的同步、异步异常在模块内记录，不向 App 或订单流程抛出。
