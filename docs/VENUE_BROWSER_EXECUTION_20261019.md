## 实现归属

70 个完整浏览器模块迁入 `client/packages/venue-browser`，保留原有功能分目录：

- `polymarket/realtime/userWs`：PM 账号私有订单/成交 WebSocket，含消息处理和取消通知。
- `polymarket/auth`：凭证解析与派生、L1/L2 鉴权签名、账号 profile。
- `polymarket/wallet` 与 `submission/client`：钱包/签名运行时、账号会话与订单客户端缓存。
- `polymarket/fok`、`gtc`、`submission`：预检、提交、确认任务、提交日志、未知提交恢复和手动卖出。
- `polymarket/orders`、`transport`、部分 `markets` 与 `quotes`：上述执行链依赖的订单事实、历史查询、仓位归因、HTTP 出口和行情读取。
- `shared/webBridge` 与 `webBridgeTypes`：浏览器宿主桥接与类型，前端安装函数设置同一实例。

另有 2 个公共模块归入已有 `@changmen/client-core`：`contract`（订单/平台契约）和 `shared/platforms`（平台常量）。它们也有 registry/Node 消费者，不归浏览器专用包。旧 adapter 路径全部保留为转出入口。

浏览器包有 114 个明确导出，不反向依赖 adapter。包内通过相对路径引用所属实现，通过公开包入口消费共有模型与契约。backend/RDS 安装闭包不包含浏览器包；前端闭包仍为 9 个 workspace。

## 行为保持与检查发现

72 个完整模块逐字比较，除静态、动态和类型导入的模块路径外，全部源码保持一致。额外核对每个导入最终指向的实现及外部依赖版本；动态加载仍在原调用位置。原状态变量、账号隔离键、签名消息、请求参数、超时重试、确认策略和持久化时序均未修改。

实际发现并修正：

1. 公共契约与平台常量若放入浏览器包，会使 registry/Node 间接加载浏览器目录；已按实际消费者归入 client-core。
2. 新浏览器包首次声明签名依赖时，缺少其局部安装记录，本机曾回退解析根目录 `@noble/hashes 1.4.0`。已补齐新包局部 `1.3.2` 的锁记录及安装；版本和完整性与原 adapter 相同，没有升级既有依赖。
3. 原测试部分 mock/spy 挂在旧入口，迁移后不能拦截实现内部调用；已调整到所属实现入口，保留原行为断言及新旧调用方混用测试。源码读取测试也调整为新实现路径；数学回放额外确认原函数片段存在，防止空片段误通过。
4. 历史源码校验读取旧入口时先精确还原本轮迁移，再执行原完整基线检查；未修改旧基线、旧哈希或扩大目录豁免。新记录覆盖 81 个既有文件、72 个新增实现，修改或缺失均须失败。
5. 兼容测试从前端消费者侧通过旧公开入口加载 marketDelay、orderSettlement、settlementJob，既验证实际包导出，又避免包内自引用；三个既有 exports 保持不变。源码依赖遍历排除新产生的局部 node_modules，仍检查全部自有实现。
