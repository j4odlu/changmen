## 引用必须有可核验的执行证据

- 每次外层验收生成随机 `invocationId`；清除旧完整审计报告，直接通过 Node 启动同一完整审计入口，传入相同 npm CLI 和环境。没有通过复用旧 Actions 任务、跨工作流绿色状态或本地通过缓存来放行。
- 完整审计报告记录实际命令数组、相对工作目录、退出码、启动/超时错误和信号；保留 commit、文件树、源码指纹、实际生产基线、captureId、兼容组合、原固定参考和全部阶段检查。
- 复用前核对完整成功、来源一致、本次运行标识、源码身份、Node/平台和环境摘要、对应阶段成功以及命令/工作目录等价。环境仅存 SHA-256 摘要，不写环境值或凭证。
- 命令对比只对 Vitest `run` 忽略明确的 JSON reporter 和 outputFile 参数，其余参数逐项相等；不能把增加排除项、换目录、减少测试或用另一个阶段当作等价。
- 每条引用保存完整报告内容哈希和阶段名；每次引用前重新核对报告与当前源码，避免运行后替换报告或源码。报告缺失、不匹配或失败直接停止，不以重新跑一次较小检查掩盖完整审计失败。
- 原封包和运输前校验继续核对必要报告原始字节哈希，并重新验证每条引用。封包后替换报告、引用阶段或内容哈希不能放行。Actions Summary 显示“直接执行”或“完整审计 / 阶段”，避免将引用耗时 0 误读为未验证。
