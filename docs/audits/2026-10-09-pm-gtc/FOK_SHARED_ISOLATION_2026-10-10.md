# FOK 共享保存与订单处理隔离验收

日期：2026-10-10。**[changmen 扩展]** 用户要求继续修复，使 FOK 保持加入 GTC 配置前的业务路径。基线固定为 `219535c8`。

本轮消除前次报告剩余的 F03 / F04：旧订单 upsert SQL、旧订单分组工具、旧提前卖出算法恢复基线内容；新增规则放到 GTC 专属保存和财务投影模块。前轮已经恢复的 RAY 时序及独立成交历史继续保留。

## 保存边界

- `server/db/rds/orders_store.js` 恢复原文件内容，包括批量 SQL、去重、参数、事务、回滚和新订单通知回调。纯 FOK 不查询 GTC 表，不取得 GTC 锁。
- `save_by_execution.js` 只按原单执行身份分流。没有 GTC 时，将原始批次数组直接交给原 `upsertOrders`；相同 Link 不构成 GTC 身份。
- 来源由已有原单、已知父买单或明确执行标记确定；GTC 专属 writer 再校验持久化 owner、账号、平台和原单身份。普通 FOK 不执行这次查询。
- 纯 GTC 原单核对等待其独立事务。FOK 整账号拉单捎带的 GTC 快照独立同步，不让 GTC 写入失败或等待阻塞 FOK 返回。GTC 财务真相仍由其原单事实事务创建和更新。
- 专属 SQL 保留 GTC 累计成交、零手续费、原 Link 和人工卖出归账；普通快照不能为已受理零成交创建财务买单，不能覆盖累计成交，也不能将卖单或对侧场馆行改写成 PM 买单。

## 分组与人工卖出边界

- `shared/orderLink.ts`、`arbEarlyLockSell.ts` 恢复基线内容，删除共享算法中的 GTC 条件。
- 旧 `OrderStore` 的业务函数体保持原样，仅把读取入口接到来源分流模块。FOK 订单对象、顺序和原分组规则保留；无 GTC 时，原 API 返回的 page 对象也直接返回。
- GTC 买单、对侧原单及父买单对应的卖单进入独立财务投影。身份使用账号、平台和原单 ID；来源已经确定的两种订单即使 Link 相同也不会合组。旧自动卖出扫描只读取 FOK 投影。
- GTC 财务列表复用原订单卡片，按执行记录分别显示；模式切回 FOK 不改变旧订单来源。顶部展示将两套统计相加，GTC 零成交不增加 PM 成交笔数。
- GTC 人工卖出落库失败的本地补丁只更新 GTC 投影，不重新塞入 FOK `OrderStore`。未决人工卖出可从 GTC 投影找到原买单恢复，已有 FOK 原单优先。
- GTC 库内 `pmShares` 为净仓；其独立展示以 `pmGtcBuyShares` 适配旧 PM 助手的“累计量减已卖量”约定，避免重复扣减。FOK 助手算法不改。
- 退出登录清除 GTC 投影与身份索引；管理端嵌入工作区另存和恢复投影，不能用另一用户的身份索引认领订单。
