# 第四轮解耦验收

范围：方案批次 3 的数据库升级兼容演练，以及共享包拆分问题的依赖核对。基线是已发布第三轮 `9aa9159ce6b531153bd5321f89f2fcd19002671e`；隔离工作树分支 `codex/decoupling-round4`。主工作区既有变更未纳入本轮。

## 交付

- 固定 52 个旧版本 Git blob 和 SHA-256，独立进程加载真实旧数据模块与结构核验器，避免把当前实现伪装成旧消费者。
- 临时 PostgreSQL 中的 16 项升级、回退和失败演练；测试 SQL 不进入生产迁移目录或初始化清单。
- 5 项引用与边界回归接入 `verification-control`；真实数据库演练提供正式 npm 命令和独立 CI 工作流，后者不需要生产密钥，不改变发布依赖。
- [数据库升级规范](../../DATABASE_UPGRADE_COMPATIBILITY.md)与[共享包边界](../../SHARED_PACKAGE_BOUNDARIES.md)。统一协议和纯逻辑继续共享，环境专属能力按入口隔离；未盲目拆包或收窄发布范围。

## 行为与限制

本轮不修改前端、后端业务实现、HTTP 调用、生产数据库结构或现有部署激活行为。日常部署继续不执行数据库维护。独立核验 CLI 对缺失必需结构非零退出，但现有发布流水线没有自动前置结构闸门；需要结构变化的发布必须按维护流程先核验再切换。

本轮旧版本演练覆盖实际数据模块与核验器，并非启动完整旧版 HTTP 服务或双跑下注流程。数据库驱动使用当前已安装依赖。后续仍需完成 action 类型映射、共享包消费者图与发布分类等剩余项。

## Bug 复核

第一次完整检查暴露既有 Cookie HTTP 测试的随机端口问题：操作系统分配端口可能命中 Node fetch 的禁用列表，请求在进入路由前以 `bad port` 失败。测试改用 Node HTTP 传输，保留原 URL、方法、Cookie/CSRF/JSON 请求及全部响应断言；10 项定向回归通过。仅修改测试文件，生产鉴权逻辑未变。首次失败日志与 verdict 单独保留。
