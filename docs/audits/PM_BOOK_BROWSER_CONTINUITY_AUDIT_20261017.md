## 停止条件与原因

1. **一个独立的公开 HTTP probe 差异样本。** 晚接入第 237.27 秒附近，资产 `910967…296382` 触发 `aligned_difference`，证据标签为 `timestamp_and_observed_depth`，HTTP 耗时约 256ms。通知只撤销该资产，Worker 没有退出，原行情继续。它满足预先使用的零差异停止条件，因此本轮不放行生产旁路。
2. **真实深度推进用例未满足。** 生命周期夹具的固定首资产 `844881…363832` 在卸载消费者前后都为 `waiting_snapshot`，结束时公共 HTTP 为 404。同 session、Worker 和消费分离均保持，但没有该资产推进证据，不能将该项记为通过。确定性浏览器注入中的卸载后深度推进另有通过证据，不替代这个真实用例。

`aligned_difference` 聚合计数为 **2**，不是两次独立事故：`record()` 记录一次 outcome，完整性撤销监听又以同名 reason 计一次。本轮统计采用 **1 条独立 probe 样本、1 次对应资产撤销**；未修改生产计数代码。控制台进度中初按聚合数表述为两次，核对后已更正。

该差异不证明 WS 丢包或 reducer 必然错误。PM 的同毫秒时间戳不是连续序号；本轮没有保存该瞬间完整 HTTP body、完整原像 hash 和前后 WS 历史，无法事后确认它是源状态差异、同毫秒多状态还是比较缺口。首段有界录制不能代替晚接入差异时刻的原始证据。**不猜根因，不删除样本，不将它改称通过。**

## 资产隔离与资源

新增浏览器合成故障夹具在同一生产 Worker 上 **24 项通过**：tick、坏深度、缺 timestamp 只撤销目标；健康资产簿与元数据原时间保留；增量不能恢复目标；新快照必须使用新资产代次；跨资产坏帧撤销全部涉及资产；移除再加入不复活旧簿；无法定位坏帧和断线整体失败关闭；重新连接等待快照；卸载诊断后 owner 存活且已知输入使健康深度继续推进。属于受控注入证据，不是真实故障发生率。
