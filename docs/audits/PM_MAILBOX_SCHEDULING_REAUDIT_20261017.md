# PM-M 被动订单簿消息调度修复复审

[changmen 扩展] 2026-10-17，`E:\River\arb\changmen`。延续 [共享服务重构审计](./PM_SHARED_ORDER_BOOK_REFACTOR_AUDIT_20261016.md)，仅修复旁路消息调度并补充浏览器证据。默认关闭、实际预检仍 HTTP、不发布、不替用户启用，不新增真实下单快路径。

## 定位与修复范围

上一轮晚接入约 300.5 秒出现 `stream_ack_timeout`，此前采样为 1 条未发送消息、0 个在途批次。错误名并不等于 Worker 卡住；原队列对待发和在途消息统一检查 1 秒年龄，而发送和 ACK 后续发都必须等待 `setTimeout(16)`。浏览器延迟该定时器时，即使 Worker 有容量，未发送尾部也不能前进。上一轮与本机回归负载重叠，缺少失效瞬间的阶段指标，不能将全部历史延迟都归因于某一种系统负载。

本轮 `realtime/orderedWorkerMailbox.ts` 改为 MessageChannel 消息任务唤醒。入队和 ACK 释放容量均可唤醒，最多挂起一个任务，空队列/无信用不循环排任务；不使用定时器维持发送节奏。批次仍按 FIFO 消费，控制消息不超车，不删改、合并或丢弃增量。单轮复制达到 2ms 后让出执行，后续使用另一个消息任务。每实例通道按需创建，stop/failure 关闭两端并清理待执行唤醒。

保持限制：8 个在途批次、每批最多 64 条/目标 256,000 字符，合计 2,048 条/2,000,000 字符/1,000ms 年龄。没有增加年龄、容量、快照期限、读簿期限或 Worker CPU 预算。消息任务仍无法消除真实主线程长时间阻塞、页面冻结或 Worker 故障；真正超过 1 秒的旧消息仍失败关闭，不冒充新鲜数据，也不自动重建 PM-M。

新增诊断区分未发送年龄、在途总年龄、发送后等待 ACK 年龄，累计最大排队/ACK 耗时；失效前保存阶段证据，清空队列后仍可审计。报文不含凭据，指标有界，不保存原始帧。

生产改动仅在独立通用消息桥；订单簿 service/store/Worker 所有权、动态消费者租约与深度接口保持上一轮拆分。没有修改 PM-M 连接、订阅、重连、心跳，或预检/签名/下单链路。两开关缺失仍关闭，经典/default/非法模式不启动该服务。没有替换 FOK 固定基线或扩大豁免。

## 回归与验收口径

确定性回归覆盖：定时器完全不运行时，消息任务仍保持 8 批背压、ACK 续发、稀疏尾部发送和完整 FIFO；超过 1 秒的待发/在途分别保留证据并失败；2ms 复制让出后仅挂一个任务，停止后无迟到发送。既有资源、服务生命周期、消费者隔离和经典行为断言保持。

浏览器使用本机独立 Chrome 测试 profile，通过 Playwright CLI 的 CDP 接入路径（`noDefaults: true`）连接。未使用其默认启动时的焦点模拟及禁用后台节流参数，没有改写 document.hidden、visibilityState 或派发模拟 visibilitychange。测试仅包含公开电竞行情、HTTP 公共簿、合成读和本机 echo Worker，不登录、不签名、不下单。

验收沿用：冷/晚接入各 15 分钟、同消息 ABBA 报价完整哈希及 P95/P99、消费者挂卸载、原连接断线恢复、经典门控/HTTP 保真、当前候选首尾复核；新增原生标签 hidden 持续至少 5 分钟并恢复前台。同流回放补采页面任务/脚本耗时，不能用报价回调耗时代表整页零成本。有效性先于放行：任一关键故障或缺证据仍为 NO-GO，不为通过而放宽限制。
