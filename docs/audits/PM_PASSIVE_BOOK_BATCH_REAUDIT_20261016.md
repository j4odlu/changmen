# PM-M 被动订单簿：批量消息桥与共享流预算复审

[changmen 扩展] 2026-10-16，工作目录 `E:\River\arb\changmen`。本次只修复已获授权的直连动态旁路，默认关闭、实际预检仍 HTTP、不发布、不启用真实下单快路径。此前真实浏览器阻断记录保留在 [原审计](./PM_PASSIVE_BOOK_BROWSER_AUDIT_20261016.md)，不覆盖历史失败证据。

## 当前结论

**NO-GO：本轮暂不放行生产旁路灰度；默认关闭、不发布。** 原来的逐帧队列与共享源 500 帧/秒适配问题已修复，最终构建通过 30 分钟前台冷/晚接入、同消息报价一致性、受控断线恢复及 12 项浏览器门控/HTTP 保真检查，未观察到新的前台队列故障或经典 FOK 回归。仍缺真实 hidden 后台调度证据；固定候选在结束检查时 10/16 返回 HTTP 404，不能代表当前有效交易候选的持续覆盖率。因此不把前台通过直接扩大为生产灰度许可，也不建议启用真实下单快路径。

剩余工作是用当前有效候选取得真实后台与前后台切换样本，并确认切换不会造成旁路不可恢复退出或拖慢原行情。当前自动化环境两次尝试切出后均报告 visible，不能用模拟 visibility 事件代替浏览器实际节流，也不能把证据缺失写成已发现后台失败。没有以扩大阈值、另建 WS、调整 PM-M 重连或放松快照期限绕过门槛。

机器汇总见 [本轮证据](./pm-passive-book-browser-repair-20261016.json)。此结论替代原审计中“正常前台流量必然队列溢出”的现状描述；原失败记录保留用于前后对照。

## 本轮修复及边界

1. 原先每帧一个 postMessage、最多 8 帧在途，正常共享流突发便耗尽信用。改为独立通用 `OrderedWorkerMailbox`：按 FIFO 聚合批次、批次 ACK 释放容量，连接状态、候选、begin/finish/cancel 与行情共用队列，控制消息不能越过旧行情。保留合计 2,000,000 字符及 1 秒年龄上限，增加 2,048 条总条目上限，8 个在途批次、每批最多 64 条。不是单纯扩大原有帧阈值，也不合并/省略中间增量。
2. 原先对全部共享输入计 500 帧/秒，未关注资产的流量也会反复作废候选。现在先在 Worker 按资产过滤，再应用原候选事件/档位限制；资源保护改为实际解析、过滤、更新及发布工作预算，每 100ms 窗口累计超过 20ms 则作废证据。单次工作无法抢占，不能宣称硬 CPU 上限。无关资产坏深度不污染候选；候选自身或无法识别身份的坏消息仍失败关闭。
3. 新增只读 coverage 报告，区分候选数、60 秒内快照数、满足全部读簿条件的数量和 miss。桥故障使用 `bridge_*` 独立计数，避免把一次失败加后续诊断完成数误称为多次桥故障。
4. 审计补修观察者容量耗尽时的 Worker 释放：注册失败立即关闭新建 Worker，不能泄漏隔离线程；后续只保留诊断失败分母直至 owner 关闭。

本轮未修改 PM-M 的订阅、重连、心跳、换线或报价提取，也未修改经典执行、签名、确认、补单、双腿顺序及订单绑定。已有只读原始流钩子仍由固定基线加精确增量检查保护，没有更新固定 manifest/hash 或目录豁免。

16ms 聚合会增加旁路队列延迟，这是减少跨线程发送开销的明确取舍。新鲜度仍按原入口接收时间计算，不在 Worker 出队时重置。实际 HTTP 不等队列，诊断本地读取时间也不代表完整预检耗时；本轮不能据此宣称交易更快。

## 模块职责

- `realtime/orderBook`：独立订单簿核心，快照整体替换、增量按绝对数量覆盖、0 删除；被动适配器没有 WebSocket、fetch、定时器或网络恢复权限。
- `realtime/orderedWorkerMailbox.ts`：通用有界 FIFO，不依赖订单簿或预检。
- `submission/preflight/optimized/wsBook`：动态旁路消费者，负责 Worker、业务新鲜度、公开 HTTP 对账和诊断；不提供执行簿 getter。
- PM-M 仍是唯一网络所有者。消费者取既有 esport 登记资产与动态候选的交集，不扩大源订阅。原报价处理先完成，旁路只读接收。
- 模式/用户退出同步终止 owner；消息代次隔离，旧报告不能复活。队列超限、超时、发送/Worker 故障只关闭旁路。实际 HTTP 的开始、完成和返回对象不等待 Worker ACK。

## 官方方法与项目选择

官方 [Market Making](https://docs.polymarket.com/trading/market-making) 建议用实时市场数据维护本地簿；[Real-Time Data](https://docs.polymarket.com/market-data/realtime-data) 提供同一市场频道的 book、price_change 等事件及 10 秒 PING 心跳。官方没有要求预检另建 WS。现有 PM-M 已接收相关官方原始数据，新建连接会重复传输同资产行情，不会天然更快或更准确。

模块独立不等于连接独立。当前被动旁路中途开始维护时可能错过初始 book，需要等待后续完整快照。若将来让通用订单簿从源订阅开始就维护，消费者晚加入可以读取既有状态；但该启动方式会影响资源生命周期，需另行评估经典用户开销。本轮不扩大模块启动范围。

60 秒完整快照期限、1 秒接收新鲜度、源时间与元数据门槛以及资源预算，均为 changmen 当前保守策略，不是官方规定。连续收到增量不必然要求官方每 60 秒重发快照；当前策略可能主动降低被动覆盖率。此次保留这些策略，不通过放松期限或补订阅提高数字。

## 浏览器方法及证据限制

真实 Brave、独立本机 `127.0.0.1:5581` 源，加载实际 PM-M/Hub/旁路客户端和最终生产 Worker。无业务登录、签名或下单。原已有开发站、后端及生产页不被操作。

使用前次公开发现的固定 118 源 token / 16 候选，保持前后负载可比。本次刷新候选时 Node 到公开 Gamma 的 TLS 连接失败，未用失败刷新冒充最新候选。固定名单可能包含已结束资产，不能代表 river 当前有效交易列表；浏览器 HTTP probe 失败原因另计，不能归因到 Node 的 TLS 错误。

30 分钟开启观测包含冷接入 900 秒、关闭 15 秒、同一连接晚接入 900 秒。每秒采样状态，每 2 秒对 16 个候选做诊断读取；这些读取没有真实 HTTP 深度和订单，只测候选新鲜度与 miss，不能用其 httpMs 或 http_shape_unknown 证明 HTTP 性能或成交率。独立公开 probe 用于同时间戳状态对账。

全流使用有界直方图，实时报价只保存前 10,000 条 hash，不用它证明完整实时序列相等。ABBA 回放使用同一真实录制前 3,000 帧，四轮全量报价 hash 才可比较。原始录制有 20,000,000 字符上限，尾部可能跳过无法放入剩余额度的帧，不能把录制跨度当作完整持续窗口。

测试页面是实际源模块加显式夹具，不是完整登录应用渲染、fo/RDS 上报或真实双腿执行。后台和受控断线另行取证；没有低端设备、长时间后台或真实成交率证明。

## 生命周期、后台尝试与 HTTP 保真

121.43 秒生命周期测试中，动态候选从 16 缩为 8，再恢复 16，未发送任何额外订阅。约 60.86 秒时夹具主动关闭自己创建的原行情连接，原 PM-M 5 秒重连机制恢复，epoch 从 1 变为 2；断开期间采样显示 assets=0、snapshots=0，结束时重新取得 6 个新鲜簿、4 个满足全部条件的候选。总计 2 次源连接、2 次源订阅，其中第 2 次来自本次明确注入的断线；Worker 只创建 1 个并持续存活。

另做 90.94 秒后台尝试，接收 81,730 帧，Worker 存活，但 91 个采样均为 visible、hidden=0。无论新建空白页还是页面点击打开同窗页，均未取得真实隐藏样本；浏览器工具也未提供标签页激活或可见性控制接口。**该结果仅是额外前台证据，后台验证未完成。** 不模拟 hidden、不将此写成后台通过，也不推断实际后台必然失败。

12 项真实浏览器门控检查全部通过：经典/缺省/非法模式不启动 Worker 或 WS；动态默认不开；显式开关才启动；切回经典同步关闭；迟到加载和退出不复活；经典与动态的正常/抛错观察者组合下，真实公开 HTTP `/book` 各只调用一次且返回对象 identity 不变，经典不调用观察者。控制器用户 store/启动导入为显式夹具，实际入口为 precheckOnly，没有签名或订单。

结束时对 16 个候选逐一做公开 HTTP 检查：6 个 HTTP 200 且通过本地 book/metadata 解析，10 个 HTTP 404。其中两个 HTTP 200 的簿一侧为空，不能把 HTTP 200 等同于双侧可成交。这个检查说明固定名单已存在显著失效，但不能追溯判定每次历史 probe_failed 都是 404，亦不能把 30 分钟覆盖分母事后从 16 改成 6。它与 Node 候选刷新 TLS 失败是两个不同证据。

## 后续启用与回滚边界

本轮不开启 river 或其他生产用户。补齐真实后台/当前有效候选验证并另获发布授权后，才可考虑 1 名直连动态用户的纯 shadow；不扩大为真实预检快路径。有效候选应来自当时实际行情及市场状态，不能只保留测试成功资产以美化覆盖。

既有开关仍为 `changmen:pm:ws-book-shadow`，缺省关闭。获准后在目标站点的目标浏览器设置值 `1` 并刷新；回滚为删除该 key 并刷新，或切回经典预检（同步停止消费者）。本段是操作说明，不是本轮开启许可。

观察 `feed=passive-pm-m`、`executionSource=existing-http`、`activeSupported=false`、worker/failure、streamEpoch、mailbox、bridge_*、coverage/miss、aligned_difference；分别记录有效候选数、资产时间采样、实际动态尝试，不能混用本次纯诊断分母。原行情性能需用浏览器相同窗口前后对照，当前生产报告没有完整页面 CPU/内存指标。

出现额外 WS/订阅、旁路引发原重连、经典行为变化、可对齐差异或明显原行情卡顿立即关闭并保留报告；队列/ACK/Worker 故障已自动终止旁路，关闭开关后再排查，不反复刷新强行恢复。持续无可比较样本时停止扩大试验，先确认候选及快照供给；不补订阅、不拿 HTTP 种 WS 簿，也不放宽现有新鲜度换取通过。
